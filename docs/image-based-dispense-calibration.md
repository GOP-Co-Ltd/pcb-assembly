# 画像ベース吐出量キャリブレーション要件

塗布前後の画像からはんだペーストの塗布体積を推定し、その日の `rotations_per_ul` へ追従する
仕組みの要件書。次の 2 つの作業を扱う。

| 作業                                               | 使うジョブ                               | 本書の節                                                                                                                                  |
| -------------------------------------------------- | ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 校正を作る（銅板へ点塗布し、撮影・計量・フィット） | `paste_volume_calibration`（1 時間規模） | [データ収集](#%E3%83%87%E3%83%BC%E3%82%BF%E5%8F%8E%E9%9B%86)                                                                              |
| 校正を使って塗布中に係数を補正する                 | `paste_solder`（はんだ塗布）             | [運転時キャリブレーション](#%E9%81%8B%E8%BB%A2%E6%99%82%E3%82%AD%E3%83%A3%E3%83%AA%E3%83%96%E3%83%AC%E3%83%BC%E3%82%B7%E3%83%A7%E3%83%B3) |

推定そのもの（直径の測り方・モデル・校正ファイル・再フィット）は
[直径ベースの塗布量校正](paste-volume-diameter-calibration.md) にある。

## 背景と範囲

オーガースクリューは短期的には回転量に比例して吐出するが、換算係数 `rotations_per_ul` は
ペーストや装置の状態で数時間〜数日のスパンで変わる。質量計測の吐出量キャリブレーション
（`dispense_calibration`）では運転開始時の状態へ追従できないので、塗布後画像から実塗布体積を
推定して係数を直す。質量計測は教師データの基準として残す。

- 対象は点塗布（`dot`）だけ。`line` / `area` は収集も推定もしない。補正する
    `rotations_per_ul` はグローバル係数なので、点塗布で得た比を全方式へ適用できる
- ノズル径・指令塗布量・吐出 rate にハードコードの制限は設けない
- 推定精度は校正の被覆域（校正データがカバーする直径の範囲）の中だけで保証する。外挿はしない
- 塗布途中のサブ秒単位のフィードバック制御はしない
- 1 回の収集または 1 回の運転時キャリブレーションの間、1 回転あたりの吐出量は一定とみなす

## 運転時キャリブレーション

はんだ塗布ジョブ `paste_solder` の中で、塗布パスの直前に実行する。専用の測定点へ既知量を点塗布し、
推定体積と指令体積の比で `rotations_per_ul` を補正する。独立したページやジョブは無い。

### 測定点

**実パッドではなく、専用の測定点を使う。** 実パッドは形状も指令量もばらばらで、点塗布に
ならないものもある。専用の測定点なら指令量を固定でき、推定がいちばん確かな直径域
（既定 0.2 μL ≒ 直径 1.0 mm）に毎回収まる。

- 測定点は基板ごとの設定で、pad editor で 1 点ずつ追加する。初回パージ点とは別の設定である
- 塗る点数は、設定した測定点の個数そのものである。機体側に点数の設定は無い
- 測定点が 0 個なら補正しない（基板へ勝手に捨て塗りをしない）
- **3 点ほど置く。** 点ごとの残差は実測で相対 9〜11 % あり、その約半分（分散の 45 %）は
    吐出そのもののばらつきである。1 点だけだと、補正したい誤差と同じ大きさの不確かさが補正値に含まれる
- **測定点の撮影範囲どうしを重ねない。** 撮影範囲は点を中心とする `crop_size_mm` 角の正方形である。
    重なるほど近いと隣のドットが写り込み、別のドットを測ってしまう。
    2 点の X の差と Y の差がどちらも `crop_size_mm` 未満なら重なり、ジョブは塗布前にエラーで止まる。
    直すには、X の差か Y の差のどちらか一方を `crop_size_mm`（既定 2.0 mm）以上にする。
    pad editor はこの範囲を点線の四角で描き、重なっている四角の色を変える
- 測定点は基板外形の内側に置く

### 設定

`machine.toml` の `[paste_dispenser.flow_calibration]` に置く。WebUI では 2 か所で編集できる。
pad editor のツールバーにある流量キャリブレーションの箱（測定点と並んでいる）と、設定ページの
「ペーストディスペンサー」→「流量キャリブレーション」である。

| キー               | 既定 | 意味                                              |
| ------------------ | ---- | ------------------------------------------------- |
| `calibration_file` | `""` | 使う校正ファイル名（空 = 機能を無効にする）       |
| `amount_ul`        | 0.2  | 1 点あたりの指令塗布量 [μL]                       |
| `crop_size_mm`     | 2.0  | 塗布前後画像の一辺 [mm]                           |
| `settle_seconds`   | 10.0 | 塗布後の撮影に入るまでの待ち [秒]（0 = 待たない） |

測定点の座標は基板設定の `flow_calibration_points` に持つ。
機能が動くのは、`calibration_file` が空でなく、かつ測定点が 1 個以上あるときだけである。

### 処理手順

はんだ塗布ジョブ `paste_solder` では、対話的ローディング（有効な場合）→ リトラクション → 初回パージの後にこの手順を実行する。
収集ジョブのローディングの位置はこれと違う（[収集手順](#%E5%8F%8E%E9%9B%86%E6%89%8B%E9%A0%86)）。

1. 全測定点の塗布前画像を撮る
2. 全測定点へ `amount_ul` を点塗布する
3. `settle_seconds` だけ待つ
4. 全測定点の塗布後画像を撮る
5. 各点の塗布体積を推定する
6. 採用できた点だけで、指令体積に対する推定体積の比 \(g\) を求める
7. `rotations_per_ul` を補正し、残りのパッドへ適用する（そのジョブの実行内だけ。`machine.toml` へは書き戻さない）

撮影・塗布・撮影を 3 パスに分けるのは、塗ってすぐ撮ると点ごとにペーストの落ち着き時間が
変わるためである。校正を作った収集ジョブと同じ並びに揃えている。
静定待ちを置くのは、測定点が数点だと塗布パスが数秒で終わり、ペーストが広がりきる前の
小さい円を測ってしまうためである（収集ジョブは 100 点規模を塗るので、塗布パス自体が待ちになる）。

### 補正式

採用できた点 \(i\) について、推定体積の合計と指令体積の合計の比を取る。

\[
g = \frac{\sum_i V_{\mathrm{estimated},i}}{\sum_i V_{\mathrm{command},i}}
,\qquad
\mathrm{rotations\_per\_ul}_{\mathrm{new}} = \frac{\mathrm{rotations\_per\_ul}_{\mathrm{old}}}{g}
\]

- 点ごとの比の平均ではなく、合計どうしの比を使う
- 新しい値は従来値の 1/3 以上 3 倍以下へ頭打ちにする。頭打ちに当たったら警告をログへ出し、頭打ちした値を使う

### 採用しない点

推定器は次の点を不採用にし、集約から外す。理由はジョブログに点ごとに出る。

| 理由                               | 意味                                         |
| ---------------------------------- | -------------------------------------------- |
| `no_deposit_detected`              | ドットを検出できなかった                     |
| `diameter_out_of_calibrated_range` | 直径が校正の被覆域の外                       |
| `diameter_below_reliable_range`    | 直径が被覆域の下端付近（信頼できる範囲の外） |
| `image_invalid: <理由>`            | 画像が構造的に不正                           |

**被覆域の下端付近は採用しない。** 被覆域が狭い校正は小径側で係数が定まらず、session 間で推定が
数十 % 食い違う。運転時キャリブレーションは、被覆域の幅の下側 35 % を除いた範囲だけを採用する。
この下限が何 mm になるかは校正ごとに変わる。1/3〜3 倍の頭打ちでは、この偏りを検出できない
（実測と根拠は [直径ベースの塗布量校正](paste-volume-diameter-calibration.md) の
「被覆域の下端は信頼できる範囲から外す」）。
`diameter_below_reliable_range` が多いときは、`amount_ul` が小さすぎる。`amount_ul` を大きくして、直径を信頼できる範囲へ入れる。
大きくしすぎると `diameter_out_of_calibrated_range` になるので、校正を作った収集の吐出量範囲の上側に収める。

### 補正できないとき

**補正できなくても塗布ジョブは失敗させない。** この時点で位置合わせと高さ計測が済んでいるので、
後から足した補正の失敗を理由に塗布そのものは取りやめない。
ただし設定の誤りは、塗布を始める前にジョブをエラーで止める。

| 状況                                                                    | 振る舞い                                      |
| ----------------------------------------------------------------------- | --------------------------------------------- |
| `calibration_file` が空、または測定点が 0 個                            | 補正せずに塗る（機能が無効）                  |
| 測定点が基板外形の外、または撮影範囲どうしが重なる                      | 塗布を始める前にジョブがエラーで止まる        |
| 校正ファイルが読めない                                                  | 警告をログへ出し、`machine.toml` の係数で塗る |
| 1 点でも塗布前または塗布後の撮影に失敗した                              | 同上（残りの点でも補正しない）                |
| 採用できた点が 0 個                                                     | 同上                                          |
| 一部の点だけ不採用                                                      | 採用できた点だけで補正する                    |
| 校正の条件（ノズル径・塗布高さ・`pixel_per_mm`・crop 寸法）が現在と違う | 食い違いをログへ出し、そのまま補正する        |

補正の結果（採用点数・推定と指令の合計体積・比・補正前後の `rotations_per_ul`・頭打ちの有無）は
ジョブログとジョブの結果サマリに出る。

## データ収集

WebUI のはんだ塗布タブの「塗布量校正の生成」（`paste_volume_calibration`）ジョブで行う。
運転者の目的は校正を作ることなので、**収集の最後に直径ベースの校正まで同じ実行で作る**。
収集した dataset は副産物として残り、`paste_volume_refit` で作り直せる
（[直径ベースの塗布量校正](paste-volume-diameter-calibration.md) の「WebUI」）。

収集は素の銅板で行い、KiCad PCB を選ばない。ジョブが外形だけの矩形銅板データを生成し、
位置・高さの基準に使う。専用の KiCad 基板も、パージも使わない。

### 収集手順

ジョブを始める前に、吐出量キャリブレーション（`dispense_calibration`）を済ませておく。

1. ジョブが設定を検証する。収まらない設定は装置を動かす前に失敗する（下の「事前に失敗する設定」）
2. 確認プロンプトに答える。吐出量キャリブレーション済みであること、ローディングで押し出したペーストを銅板の外へ捨てることを確認する
3. 未塗布の銅板を電子天秤に載せて TARE し、同じ銅板を装置へ設置する
4. ジョブが矩形銅板データを生成し、位置と高さを計測する
5. ジョブが全セル（blank を含む）を全 view で塗布前撮影する。この間ディスペンサーは有効にしない
6. ノズルが銅板の外へ移動したら、運転者がインタラクティブにローディングしてプライム状態を整える。押し出したペーストは銅板へ落とさない
7. ジョブが blank を除く全セルへ点塗布する
8. ジョブが全セル（blank を含む）を全 view で塗布後撮影する
9. ジョブが計量質量以外を確定させた `pending.json` を session へ書く
10. 入力待ちになると機体のスピーカーが鳴る。TARE した電子天秤で銅板の増加質量 [mg] を量り、入力する
11. ジョブが教師体積を計算して dataset を確定し、ZIP を artifact にする
12. ジョブが校正をフィットして保存する

手順 5〜8 で失敗・中断したときは、取得済みファイルを `*.incomplete` として残す。

#### 手順 10 で質量を入力できなかったとき

撮影済みの session は `pending.json` 付きで残っている。撮り直さず、同じタブの
「未完了 dataset の確定」（`paste_dataset_finalize`）ジョブで確定する。装置も PCB も使わない。

1. 塗布済みの銅板を拭かずに、TARE した電子天秤で増加質量 [mg] を量る
2. `paste_dataset_finalize` のパラメータに増加質量を入れて実行する
3. 実行時のプロンプトで対象 session を選ぶ（候補は `pending.json` を持つ `*.incomplete` と `.<stem>.tmp`）
4. ジョブが `metadata.json` を書き足し、directory を完成名へ rename する。撮影済み画像は書き直さない

#### 手順の理由と禁止事項

- **ローディング分を銅板へ落とさない。** 落ちると計量した増加質量に混ざり、回転数比の配分を通じて全 sample に系統的なバイアスがかかる。装置の外からは観測できないので、確認プロンプトで運転者に確認させる
- **ローディングは塗布前撮影の後、塗布パスの直前に行う。** 塗布前撮影より先に行うと、数十分の撮影のあいだにプライム状態が失われるためである
- **撮影パスではディスペンサーを有効にしない。** AirPump を入れたまま数十分ヘッドを動かすと、加圧されたノズルからペーストが垂れて塗布前画像と blank セルが汚れる
- **ジョブ先頭でリトラクションしない。** 塗布シーケンスはリトラクション量を prime してから同量を retract する自己完結型である。先頭で retract すると、plunger が baseline より引き込まれた状態で全点を塗布することになる
- **prime 後の追加遅延は 0 に固定する。** 追加遅延中の押し出し量は指令量に依らず一定なので、小さい量の点でラベルに偏りが出る
- **`pending.json` を計量より先に書く。** 計量質量は収集で唯一、装置の外から来る値である。最後の入力にだけ依存して 1 時間ぶんの撮影を失わないようにする
- 3 パスにすると、先頭の点は塗布から塗布後撮影まで数十分空く。照明・カメラの自動利得・熱ドリフト・ペーストのスランプが差分に含まれるので、blank セルと `samples[].order` から事後に検出する

### ジョブフォームのパラメータ

既定値はコア層の DTO（`pcbasm.pasting.dataset.plan`）の既定が唯一の出典である。

| name                           | 表示                                 | 既定              |
| ------------------------------ | ------------------------------------ | ----------------- |
| `plate_width` / `plate_height` | 銅板の幅 / 高さ [mm]                 | 40.0              |
| `tolerance`                    | 位置合わせ許容誤差 [mm]              | 0.1               |
| `edge_margin`                  | 外周余白 [mm]                        | 2.0               |
| `cell_size`                    | セル寸法 [mm]                        | 2.0               |
| `cell_gap`                     | セル間隔 [mm]                        | 1.0               |
| `crop_size`                    | 撮影 crop 寸法 [mm]                  | 2.0               |
| `loading_amount`               | 体積ローディング量 [uL]              | 0.1               |
| `loading_rotations`            | 回転ローディング回転数 [rev]         | 5.0               |
| `loading_rate`                 | 回転ローディング角速度 [rev/s]       | 0.5               |
| `loading_accel`                | 回転ローディング角加速度 [rev/s^2]   | 0.5               |
| `loading_retract_rotations`    | 回転ローディング引き戻し回転数 [rev] | 0.0               |
| `paste_height`                 | 塗布高さ [mm]                        | 0.2（必須・正値） |
| `volume_min` / `volume_max`    | 吐出量の下限 / 上限 [uL]             | 0.05 / 0.2        |
| `volume_divisions`             | 吐出量の分割数                       | 5                 |
| `samples_per_volume`           | 1 量あたりのサンプル数               | 3                 |
| `blank_count`                  | blank セル数                         | 4                 |
| `view_count`                   | 周辺 view 数（0 = 中心のみ）         | 0                 |
| `view_offset`                  | view の移動距離 [mm]                 | 1.0               |
| `shuffle_seed`                 | 配置シード（0 = 実行ごとに生成）     | 0                 |
| `paste_id`                     | ペースト製品ID                       | 必須              |
| `paste_lot`                    | 製造ロット                           | 任意              |

- `paste_id` にはメーカー名・製品名、または社内管理用の品番を入れる。`paste_lot` には容器に記載されたロット番号を入れる。同じ製品でもロット・保管期間・開封後時間で吐出量が変わり得るので、後から分類・追跡するために metadata へ残す
- このほかに検出ハイパラ・blank 検証・校正の保存名・検証に使う既存校正の欄がある。意味は [直径ベースの塗布量校正](paste-volume-diameter-calibration.md) を参照する

### セル格子と吐出量の割り当て

銅板には solder mask のダムが無いので、パッド形状ではなくセル格子で塗布位置を決める。

- 有効領域は、銅板から外周余白を四方引いた矩形である。除外領域は無く、格子セルはすべて使える
- 有効領域へ一辺 `cell_size` のセルを、`cell_size + cell_gap` のピッチで行優先に敷く
- 1 セルに 1 点だけ塗る。塗布高さは `paste_height` の数値を使い、膜厚追従の `auto` は使わない
- 吐出量列は `volume_min` から `volume_max` を `volume_divisions` 点に等分した昇順列である。`volume_min == volume_max` なら量 1 種になる
- 塗布サンプル数は `volume_divisions × samples_per_volume`（既定 15）で、これに `blank_count` を足したものが撮影対象セル数である
- blank セルは塗布せず、塗布前後の画像だけを撮って真値 0 の sample にする。移動中のドロールが板へ落ちていないかの検出も兼ねる
- 使うセルは、格子から撮影対象セル数ぶんをシード付きで無作為に選ぶ。先頭から詰めると上端数行に固まり、照明ムラ・反り・端部の反射の影響が帯状に偏るためである
- 吐出量と blank は、選んだセルへシード付きシャッフルで配る。板上の位置と吐出量の相関をなくすためである。同じシードなら使うセルと割り当てが再現する。実際に使ったシードは metadata に残る

### view と crop

- 各セルは中心 view を撮る。`view_count` が 1 以上なら、中心から `view_offset` 離れた周辺 view も撮る。周辺 view の角度は +X を 0 度として反時計回りに 360/`view_count` 度ずつ回す
- **`view_count` は 0 のままでよい。** 周辺 view は検出失敗時のフォールバックであり、精度は上がらない。実測では 831 サンプルで検出失敗 0 件、view 間ばらつきは体積換算 1.2 % で、撮影枚数だけが view 数に比例して増える。検出失敗が出るときだけ増やす
- crop は一辺 `crop_size` の正方形である。隣セルの写り込みを防ぐため `crop_size <= cell_size + cell_gap` を強制する
- crop のピクセル寸法は収集開始時に `crop_size × pixel_per_mm` から 1 回だけ決め、奇数に寄せる。1 session の全画像が同じピクセル寸法になる
- mask 画像は保存しない。塗布後の円径が事前に分からないためである

### 事前に失敗する設定

次の設定は、装置を動かす前にジョブを失敗させる。

- `crop_size` がセルピッチ（`cell_size + cell_gap`）より大きい
- 撮影対象セル数が格子のセル数を超える
- `volume_min × rotations_per_ul` が最小指令回転数（ペーストスクリューのステッパー 200 step/rev × 64 分割の 1 マイクロステップ）を下回る
- view offset を足した crop が camera frame からはみ出す（padding はしない）
- 撮影位置、またはノズルの塗布位置がステージ可動域の外に出る（塗布位置は撮影位置からツールヘッドオフセットぶんずれるので別に検証する）

### 位置合わせ

銅板には照合する銅箔パターンが無いので、通常のはんだ塗布の領域照合・pad 中心照合は使わない。
基準点計測で得た board 変換と、板外形を銅箔とみなして計測した高さ面だけを使う。
crop はセル中心を狙う固定寸法の窓なので、数十 µm の系統誤差は窓内で点がわずかに寄るだけで済む。

### 教師体積

セル \(i\) の教師体積は、計量した総質量をスクリュー回転数の比で配分して求める。

\[
V_i = \frac{m_{\mathrm{total}}}{\rho}\,\frac{r_i}{\sum_j r_j}
\]

- \(m_{\mathrm{total}}\): TARE 後の増加質量 [mg]
- \(\rho\): ペースト密度 [mg/µL]。`machine.toml` の `[paste_dispenser]` の `solder_paste_density`（既定 3.78）を使う
- \(r_i\): セル \(i\) の指令回転数 [rev]（塗布セルだけで和を取る。blank は含めず真値 0）

ローディングで押し出した分は銅板の外へ捨てるので、\(m_{\mathrm{total}}\) にも配分にも入らない。
実績量は metadata の `loading` に記録だけする。

**ラベルの限界。** この配分では点ごとのラベルが「指令量 × 単一係数」になり、点ごとの実際の
ばらつきはラベルに入らない。運転時のグローバル係数の補正には足りるが、点ごとの誤差は評価できない。
これを補うため、次を記録する（点ごとの個別計量はしない）。

- `label.kind = "rotation_allocated"`: 将来の直接計量ラベルと区別する
- blank セル: 原点に独立な真値を 1 種入れる
- `samples[].order`（塗布実行順）: session 中の流量ドリフトを事後に検出する

## データセット形式

### ディレクトリ構造

1 回の収集を 1 session とし、`data/paste-volume-datasets/<銅板名>-<収集時刻>/` に置く。

- 銅板名は `plate-<幅>x<高さ>`、収集時刻は 3 桁の millisecond と timezone を含む
- 生成 session はこの directory の `.gitignore` で Git 管理から外れる
- 書き込み中は `.<stem>.tmp` を使い、完成時に完成名へ atomic rename する。失敗・中断時は `<stem>.incomplete` として残す
- 未確定の session は、計量質量だけが欠けた `pending.json`（schema v1）を持つ。これは `metadata.json` から質量に依存する値（`total` と sample の `measured_volume_ul`）を抜いたものである。確定した session は `pending.json` を持たない

```text
data/paste-volume-datasets/
├── .gitignore
└── plate-40x40-20260908T143052.123+0900/
    ├── metadata.json
    ├── pre/
    │   ├── 000001.00.png
    │   ├── 000002.00.png
    │   └── ...
    └── post/
        ├── 000001.00.png
        ├── 000002.00.png
        └── ...
```

- 画像ファイル名は `<sample番号>.<view番号>.png`。sample 番号は塗布セルと blank セルで同じ採番列を共有する
- `pre/` と `post/` の同名ファイルが 1 組である
- 画像は lossless PNG で、全画像が `config.crop_size_px` の正方形である

## 設計方針

- 実機を動かす操作はすべて WebUI のジョブとして提供し、専用の CLI は持たない
- 計算とドメインルール（セル格子、教師体積の配分、塗布量の推定、`rotations_per_ul` の補正計算）は `src/pcbasm/` の公開 API に置く。`src/web/` のジョブと router は入出力変換・prompt・progress・artifact 変換だけを担う
- frontend は backend が返す値をそのまま表示し、体積・教師 label・補正係数・点数・撮影枚数を JavaScript で再導出しない
- 収集ジョブのフォームの下に配置プレビューを置く。フォームの値が変わるたびに `POST /api/pasting/paste-dataset-layout` を呼び、点数（塗布 / blank）・view 数・撮影枚数・格子セル総数・配置シード・配置図を表示する。装置を動かさないので操作権は要らない。配置不能でも図は消さず理由を併記する。シードが 0 のときの図は暫定配置である
- 配置プレビューのリクエストのキーはジョブの `ParamSpec` 名と一致させ、レイアウトに関係しない `tolerance` / `paste_height` / `paste_id` / `paste_lot` とローディング設定は送らない。配置図では使用セルを吐出量で色分けし、blank を破線で描く
- 収集ページのローディング操作 UI は `partials/loading_controls.html` を流用する。収集はパージをしないので、初回パージ位置の選択欄は無い
- 次の機能は実運用で必要になるまで作らない。dataset 画像の gallery、体積分布の対話グラフ、frontend での推論・label 計算・補正計算

## 達成条件

- 教師ラベルは回転数比の配分なので、点ごとの誤差は原理的に評価できない。**主基準は session 総体積の相対誤差**とし、点ごとの誤差は参考値に留める（理由と実測は [直径ベースの塗布量校正](paste-volume-diameter-calibration.md) の「達成条件が「session 総体積の誤差」である理由」）
- blank セルの検出直径が 0 で、検出失敗が 0 であることを回帰条件にする
- 既定の中心 1 view（`view_count = 0`）で推定が成立すること。周辺 view を足した場合との精度の差は評価 report に残す
- Raspberry Pi 5 上で、前処理済みの 1 view 1 sample を 1 秒以内に推定する
- 採用できた推定が 1 個以上あれば補正値を算出できる
- パージ点と実パッドを運転時キャリブレーションへ混ぜない

## 未確定事項

- 自動補正に採用する `std / mean` の閾値（現状は閾値を設けず、採用条件は上の「採用しない点」だけ）

## 付録: テスト塗布基板

`dot` / `line` / `area` を実基板形状で試すための KiCad 基板を生成する機能で、**データ収集には使わない**。
塗布パラメータの目視確認やテスト塗布に使う。実装は `pcbasm.pasting.testboard`
（`config` / `catalog` / `layout` / `generator`）にある。公開名に曖昧な `calibration_board` は使わない。

### 設定と既定

- 基板 40 × 40 mm、外周余白 1 mm、パッド間余白 1 mm
- purge pad 2 × 2 mm を左上の外周余白の内側に固定する。通常パターン領域との間隔は 1 mm
- 流量計測パッドは、収集と同じ点塗布で吐出量を確かめるための正方形パッドで、大きさと個数（0〜1,000、既定 2 mm 角 × 5 個）だけを持つ。purge pad の右へパッド間余白を挟んで並べ、有効領域の右端で下へ折り返す。収まらなければ配置不能として理由を返す
- 初期レシピは `R_0402` / `R_0603` / `R_0805` / `R_1206`（回転分割数 4・繰り返し数 3）と `SOT-23` / `SOT-23-5`（4・2）の代表パッド種。回転範囲はすべて 180 度

### パッド種と複製

- 配置単位は部品ではなく、footprint から抽出した 1 種類のパッド形状（パッド種）である。F.Cu / F.Mask / F.Paste の実ポリゴン・pad 属性・drill 形状が一致し、0/90/180/270 度の回転で重なるパッドを同じ種にまとめる。レイヤーや形状が違うもの（QFN の外周リードと exposed pad など）は別の種にする
- 各パッド種を回転分割数 `n`・繰り返し数 `m` で独立した矩形として複製する。回転範囲を `theta`（`0 < theta <= 360`、既定 180 度）とすると、回転 index `i` の角度は `i × theta / n`（`0 <= i < n`）。`n >= 1`、`m >= 1`
- 全パッド種の `n × m` の合計は 10,000 以下（リソース枯渇の防止）
- パッド間隔は各回転角の F.Cu / F.Paste の AABB で計算する。配置方向のオプションは無い
- 配置は常に自動最適配置で、複数のサイズ順と MaxRects の評価方法を試し、使用領域の面積・高さ・幅の順で最小のものを採る。purge pad と流量計測パッドを余白ぶん広げた矩形を keepout にする

### 候補の検索と任意パッド

- 候補はインストール済み KiCad 9 footprint root の全 `*.pretty/*.kicad_mod`。root は `KICAD9_FOOTPRINT_DIR` で上書きでき、未指定なら `/usr/share/kicad/footprints`
- 起動時はファイル名の検索 index だけを作り、選んだ footprint だけを pcbnew で読む。選んだ footprint の未追加のパッド種を 1 操作ですべて追加し、既にあるパッド種は重複させない
- 検索語が空なら、はんだペースト印刷で一般的な footprint の一覧を出す（一覧は `catalog.py`。BGA など通常のペースト印刷対象でない package は入れない）
- 任意サイズのパッドを、円（直径）・矩形（幅・高さ）・角丸矩形（幅・高さ・角丸半径）・長円（幅・高さ）で追加できる。F.Cu / F.Mask / F.Paste を持つ SMD パッドとして生成し、長円は穴あきの slot にしない。名称を省略すると形状と寸法から自動で付ける

### 生成物と WebUI

- 各配置位置に、抽出したパッド 1 個だけを持つ footprint を置く。元 footprint の silkscreen は複製しない。reference / value 文字は非表示で、reference は通常パッドが `PAD1` からの連番、purge pad が `PURGE`、流量計測パッドが `FLOW1` からの連番（pad number はすべて `1`）
- WebUI は「はんだ塗布」タブの「テスト塗布基板生成」。装置を動かさないので操作権は要らない。preview は解決済みの F.Cu / F.Paste と角度を SVG で描き、部品名は hover の tooltip に出す
- 配置領域を超えても preview は消さず、はみ出した部分を赤で重ね、配置可能になるまで基板生成を無効にする
- 設定は `pcbasm-paste-test-board.json`、基板は `pcbasm-paste-test-board.kicad_pcb` としてブラウザへダウンロードする
- 編集中の設定は機体ごとにブラウザの localStorage に保存し、再読込時にサーバーの Import API で検証・正規化してから復元する。古い schema や不正な内容は破棄して初期設定に戻す。サーバー側には保存しない
- 表示順の並べ替え（名称・パッド種の見出し）は、設定の正規順や基板上の配置順を変えない。正規順はサーバーが返す値を正とし、WebUI で再導出しない

### 設定 JSON

- `kind: "paste_test_board"`、`schema_version: 1` を必須とする。トップレベルは `board` / `purge_pad` / `flow_pads` / `custom_pads` / `patterns`
- Import は必須キー・未知キー・値の型・ドメイン制約を厳密に検証し、文字列から数値への暗黙変換をしない。妥当な設定はサーバーの安定順へ正規化する
- 配置不能でも、構造が正しい設定は Export できる
