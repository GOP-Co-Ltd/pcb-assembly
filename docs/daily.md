# 日常の運用

[ドキュメント一覧](../README.md) · 前: [立ち上げ](commissioning.md) · 次: [保守ガイド](maintenance.md)

[立ち上げ](commissioning.md) を済ませた機体で、日々の塗布と、そのまわりの作業を行う手順。

## 画面の見方

機体の UI（`http://<ホスト名>.local:8080`）を開くと、自機の塗布ページに着く。frontend 専用のホストなど自機が無いときは機体一覧に着く。

1. トップバーで対象の機体を選ぶ。機体を切り替えると、その機体の状態と設定が出る。
2. 装置を動かす前に、操作権の「取得」を押す（[操作権](#%E6%93%8D%E4%BD%9C%E6%A8%A9)）。
3. トップバーの PCB ファイル名（未選択なら「PCB未選択」）から `.kicad_pcb` を選ぶ（[PCB ファイル](#pcb-%E3%83%95%E3%82%A1%E3%82%A4%E3%83%AB)）。
4. 上部のタブで作業分野を選び、左の一覧から機能を開く。タブはそのタブの先頭の機能を開く。
    スマートフォンでは「機能を選択」を開くと一覧が出る。
5. パラメータを確かめてジョブを実行し、進捗・ログと画面に出る質問を見る。終わったら成果物を確かめる。

| タブ | 主な用途                                                                                                                   |
| ---- | -------------------------------------------------------------------------------------------------------------------------- |
| 塗布 | はんだ塗布、ローディング、高さ計測、ノズルクリーニングのテスト                                                             |
| 校正 | 立ち上げチェックリスト、カメラ校正とプレビュー、基準点・巡回・直交性・銅箔検出、ノズル位置とプローブ、吐出量・塗布量の校正 |
| 基板 | テスト塗布基板・格子基板・矩形基板の生成、PCB の情報の抽出、塗布範囲の確認                                                 |
| 機体 | Klipper ステータス、装置診断、マシン設定、通知音、設定履歴とバックアップ                                                   |

トップバーには、機体一覧、ソフトウェア更新のバッジ、立ち上げが残っているときのチップ、緊急停止、再起動（復旧）が並ぶ。
スマートフォンやタブレットでは、上部の「操作・設定」に操作権・PCB 選択・設定・再起動がまとまる。機体の選択と緊急停止はメニューの外にあり、スクロール中も上部に出る。

ジョブの中止は実行中の処理を止める操作、緊急停止は装置を止める操作で、どちらも操作権が無くても押せる。
緊急停止の後は、トップバーの「再起動（復旧）」で使える状態へ戻す（[保守ガイドの復旧](maintenance.md#%E5%BE%A9%E6%97%A7)）。

### ジョブの質問に答える

- 数値の質問は値を入れて答える。空欄は送らないので、`0` も明示して入れる
- 「中止」が出ている質問は、空欄のまま中止できる
- 回答欄はサーバーが受け付けてから閉じる。送信の失敗や操作権の切替で断られたときは、入力が残る

### 校正の結果を反映する

校正のジョブが終わって「設定に反映」が出たら、結果を確かめて反映するか「破棄」を押す。
別の画面から次のジョブを始めると、古い結果への操作は断られる。「ジョブが切り替わりました」と出たら、表示中の結果を確かめ直す。
反映・破棄は、同じ機体を開いているほかの画面にも同期される。

反映で校正ファイルを保存できなかったときは、`machine.toml` は変わらず、結果は再試行できる状態で残る。
backend のログ（[ログを見る](maintenance.md#%E3%83%AD%E3%82%B0%E3%82%92%E8%A6%8B%E3%82%8B)）で原因を確かめ、設定ディレクトリの書込権限・空き容量・同名のディレクトリを調べる。
直したら、同じ結果の「設定に反映」をもう一度押す。
残るのは直近のジョブの結果だけなので、再試行の前に別のジョブを始めない。サービスを再起動するなら、先に結果欄から校正 JSON をダウンロードしておく。

## 基板を塗る

### PCB ファイル

ファイルブラウザに出るのは、機体（backend）のファイルである。frontend のホストのファイルは見えない。
**USB メモリはその機体の Raspberry Pi に挿す。** 開ける場所はリポジトリ直下、`/media`、`/mnt` だけ。

- 一覧は Tab / Shift+Tab で移り、Enter でフォルダーを開くか PCB を選ぶ。「上のフォルダー」で戻り、Esc か「閉じる」でやめる
- ブラウザの端末にあるファイルは「この端末からアップロード」で送る。`uploads/` に保存され、そのまま選ばれる。同じ名前のファイルは上書きする
- 基板ごとの塗布設定は PCB の置き場所に結び付く。同じ PCB を別の場所へ移すと、設定は初期値に戻って見える

選択の保存に失敗すると、選択は前のまま残る。アップロードでは、選択の保存に失敗してもファイルだけは残ることがある。
backend のログと、データディレクトリの書込権限・空き容量を確かめ、直してから同じ操作をやり直す。

### はんだ塗布（`paste_solder`）

塗布タブの「はんだ塗布」で、パッドの設定表を整えてから実行する。

1. 設定表で、塗らないパッドを無効にし、塗布方式や量を変えたい行だけ上書きする。上書きは部品・形状などの階層ごとに書け、`×` で継承に戻る。Auto の欄の横には、実際に塗る方式（例: `→ 点 12 / 線 6`）や計算した高さ（例: `auto (0.050 mm)`、微小線の終点高の既定は `始点に従う (0.050 mm)`、pad で違えば範囲）が出る
2. 経路・塗布経路・銅箔・初回パージのプレビューで、塗る場所と順番を確かめる
3. 基板をセットして実行する。ジョブは高さ計測 → 位置合わせ → 初回パージ → 塗布の順に進み、終わるとノズルキャップへ駐機して脱力する

設定表はキーボードでも編集できる。

- `Tab` / `Shift+Tab` で欄を移る。行頭の開閉ボタンは `Enter`、有効・無効のチェックボックスは `Space`
- 数値は `Enter` か別の欄へ移ると保存される。保存の後も操作位置は残り、`×` の後は対応する入力欄へ戻る
- 同じ PCB では、ほかの項目の保存や銅箔表示の読み込みが終わっても、入力中の数値と手動高さモードは残る

編集の直後に実行しても、パッドの設定と、同じページの設定欄（`machine.toml`）の保存が終わってからジョブを始める。
保存に失敗したら始めずにエラーを出すので、入力と接続を確かめてから実行し直す。
ジョブのフォームの値のうち次回の初期値になる項目は、入力したそばから保存される。

設定欄が空欄の項目は、`machine.toml` に書かれていない。欄に薄く出る値が、そのとき実際に使われる既定値である。
キーの一覧は [設定キー一覧](reference/config.md) にある。

### 所要時間（予測と実測）

はんだ塗布ページの実行パネルに「予測所要時間」が出る。パッドの有効・無効や塗布の設定を変えると取り直す。
内訳は塗る pad の数と、前段・塗布の時間である。

- 前段: 位置合わせ・高さ計測・初回パージ・終了後の退避など、pad 数に依らない時間。設定ページの「所要時間の予測」（`solder.tact.setup_sec`、既定 300 秒）の値をそのまま足す
- 塗布: pad ごとの塗布経路を、接近 → 下降 → prime と吐出 → retract と上昇の順に積んだ時間。移動の速度と加速度は printer.cfg の `max_velocity` / `max_accel`（Z は `max_z_velocity` / `max_z_accel`）を使う

Klipper に接続できないときは printer.cfg を読めないので、予測を出さずに理由を出す。

実測は、ジョブコンソールの状態の横に「経過」として出る。実行中は毎秒進み、終了後のノズルキャップへの退避を終えると止まった値が残る。
予測と実測がずれるときは、塗布を 1 回通してから `solder.tact.setup_sec` を合わせる。
pad 数を変えてもずれ方が変わらなければ前段の時間の差なので、ずれた分だけ `solder.tact.setup_sec` を増減する。

### ローディングと高さ計測

- ローディング（`loading`）: シリンジを替えたあとにペーストを送り出す。開始時に全軸ホーミングし、位置の X / Y / Z を指定していれば指定した軸だけそこへ移る。その後、押出・回転押出・ジョグをメニューで繰り返す
- 高さ平面計測（`height_plane`）: 選んだ PCB の銅箔上をプローブで測り、計測点と高さ面のヒートマップを成果物に出す。塗布ジョブも塗る前に同じ計測を行う

### ノズルの清掃

塗布ジョブは初回パージを塗布の前後で撮り、ペーストが写らなければ、ノズル先端をクリーニング位置でこすってからもう一度だけパージする。
掃除しても写らなければ、塗布を始めずにジョブを止める。撮影や計測ができなかったときは、確かめずに先へ進む。

クリーニングの動きだけを試すときは、塗布タブの「ノズルクリーニングのテスト」（`nozzle_clean_test`）を使う。
未ホーミングならホーミングしてから、記録した位置と設定で prime → クリーニング → リトラクトを 1 回行い、キャップへ駐機する。
位置は校正タブの「ノズル位置の設定」で記録し、押し込み量・こすり幅・往復回数などは設定ページの「ノズルクリーニング」で変える。

## 複数の機体を扱う

トップバーの「機体一覧」は、登録済みの全機体を 1 行ずつ並べる。行ごとに、操作権、更新の有無、立ち上げの状況、塗布の実行がある。

- 操作権は機体ごとに別にある。行の「取得」「解放」でその機体の操作権だけを動かす。ほかの人が持っている機体は、機体名のリンクから機体のページを開いて奪取する
- 「塗布実行」は、その行の操作権が「あなた」のときだけ押せる。その機体で選択中の PCB と保存済みの塗布設定、`paste_solder` の既定のパラメータ（対話的ローディングはオフ）で塗る。PCB が未選択なら始まらない
- パラメータを変えて塗るとき、進行を見るとき、止めるときは、行の「塗布ページ」から塗布ページを開く
- 「接続できません」の行は操作できない。機体とつながると自動で戻る
- 「ソフトウェア」の欄は更新の有無、「立ち上げ」の欄は立ち上げの要約を示す。押すと更新ページと立ち上げチェックリストを開く

機体一覧を閉じても操作権は残る。作業を終えたら行の「解放」を押す。
機体が一覧に出ないときは [機体の登録](maintenance.md#%E6%A9%9F%E4%BD%93%E3%81%AE%E7%99%BB%E9%8C%B2) を確かめる。

### 操作権

装置を動かす操作は、操作権を持つ 1 つのセッションだけができる。閲覧は誰でもできる。

- **緊急停止とジョブの中止は、操作権に関係なく誰でも押せる。** 安全のための操作なので制限しない
- 画面上部のバーで、空いていれば「取得」、自分が持っていれば「解放」、ほかの人が持っていれば「奪取」を押せる。奪取された人は閲覧だけになる。実行中のジョブは奪取しても止まらない
- 操作権は時間では切れない。持っている人が外れるのは、「解放」を押したとき、ほかの人が「奪取」したとき、backend が再起動したとき（更新と再起動（復旧）で起きる）の 3 つだけ
- 前の人が操作権を持ったまま席を外していたら、待たずに奪取する。作業を終えたら解放する
- **操作権は認証ではなく自己申告である。** セッションは frontend が発行する cookie で、LAN の誰でもほかの人を名乗れる。防ぐのは複数の人が同時に指示を出すことだけ
- ブラウザのプロファイル 1 つを 1 人として扱う。共有端末の同じブラウザを使う 2 人は、同じセッションになる

**WebUI に認証は無い。** LAN から接続できる人は誰でも装置を動かせ、機体の `/media` と `/mnt` を読める。
信頼できない範囲へ公開するなら、ファイアウォールか前段のリバースプロキシで認証をかける。

## 通知音

機体の Raspberry Pi につないだスピーカーから、backend が通知音を鳴らす。ブラウザからは鳴らない。

| 音         | 鳴る場面                                                 |
| ---------- | -------------------------------------------------------- |
| 成功音     | 装置を動かすジョブが成功した                             |
| 失敗音     | 装置を動かすジョブが失敗した（手動の中止では鳴らさない） |
| 入力待ち音 | ジョブが質問を出したとき、ボタン操作を待ちに入ったとき   |

成功音と失敗音は装置を動かすジョブだけが鳴らす。PCB の生成や再フィットのようにすぐ終わるジョブでは鳴らさない。

機体タブの「通知音」で出力デバイスと音量を選び、テスト再生で確かめる。テスト再生はスピーカーが実際に鳴るので操作権が要る。
設定は `machine.toml` の `[audio]` に入る。書いていなければ ALSA のシステム既定のデバイスで鳴る。

音を差し替えるときは、`src/pcbasm/hal/sounds/` の `success.wav` / `failure.wav` / `prompt.wav` を、非圧縮 16-bit PCM の WAV で同じ名前のまま上書きする（Git LFS で追跡している）。

## 塗布量のデータセットを集める

画像による流量補正は、塗布量の校正ファイルを使う。ペーストの種類やノズル径を替えたら、校正タブの「吐出量・塗布量」で作り直す。

| 機能                       | すること                                                                                           |
| -------------------------- | -------------------------------------------------------------------------------------------------- |
| `paste_volume_calibration` | 銅板へ点を塗って撮り、銅板の質量を量ってデータセットにし、校正ファイルを作る                       |
| `paste_volume_refit`       | 保存済みのデータセットから、検出のパラメータを変えて校正ファイルを作り直す                         |
| `paste_dataset_finalize`   | 質量を入力できずに残った収集（`pending.json` 付きの `*.incomplete`）を、後から質量を入れて確定する |

データセットは `data/paste-volume-datasets/`、校正ファイルは `data/paste-volume-calibrations/` に入る。校正ファイルは Git で管理し、機体の間で配る。
作った校正ファイルは、塗布ページの「校正ファイル」（運転時補正）で選ぶと塗布に使われる。

### 集める手順

収集は 1 時間ほどかかり、KiCad の PCB は使わず素の銅板に塗る。電子天秤を用意し、吐出量の校正（`dispense_calibration`）を済ませておく。

1. ジョブが設定を検証する。収まらない設定は装置を動かす前に失敗する（[事前に失敗する設定](design/image-based-dispense-calibration.md#%E4%BA%8B%E5%89%8D%E3%81%AB%E5%A4%B1%E6%95%97%E3%81%99%E3%82%8B%E8%A8%AD%E5%AE%9A)）
2. 確認プロンプトに答える。吐出量キャリブレーション済みであること、ローディングで押し出したペーストを銅板の外へ捨てることを確認する
3. 未塗布の銅板を電子天秤に載せて TARE し、同じ銅板を装置へ設置する
4. ジョブが矩形銅板データを生成し、位置と高さを計測する
5. ジョブが全セル（blank を含む）を全 view で塗布前撮影する。この間ディスペンサーは有効にしない
6. ノズルが銅板の外へ移動したら、運転者がインタラクティブにローディングしてプライム状態を整える。押し出したペーストは銅板へ落とさない
7. ジョブが blank を除く全セルへ点塗布する
8. ジョブが全セル（blank を含む）を全 view で塗布後撮影する
9. ジョブが計量質量以外を確定させた `pending.json` を session へ書く
10. 入力待ちになると機体のスピーカーが鳴る。TARE した電子天秤で銅板の増加質量 [mg] を量り、入力する
11. ジョブが教師体積を計算して dataset を確定し、ZIP を artifact にする
12. ジョブが校正をフィットして保存する

手順 5〜8 で失敗・中断したときは、取得済みファイルを `*.incomplete` として残す。
手順の理由と、してはいけないことは [画像ベース吐出量キャリブレーション要件](design/image-based-dispense-calibration.md#%E6%89%8B%E9%A0%86%E3%81%AE%E7%90%86%E7%94%B1%E3%81%A8%E7%A6%81%E6%AD%A2%E4%BA%8B%E9%A0%85) にある。

### 手順 10 で質量を入力できなかったとき

撮影済みの session は `pending.json` 付きで残っている。撮り直さず、同じタブの「未完了 dataset の確定」（`paste_dataset_finalize`）ジョブで確定する。装置も PCB も使わない。

1. 塗布済みの銅板を拭かずに、TARE した電子天秤で増加質量 [mg] を量る
2. `paste_dataset_finalize` のパラメータに増加質量を入れて実行する
3. 実行時のプロンプトで対象 session を選ぶ（候補は `pending.json` を持つ `*.incomplete` と `.<stem>.tmp`）
4. ジョブが `metadata.json` を書き足し、directory を完成名へ rename する。撮影済み画像は書き直さない

## 困ったとき

| 症状                       | 確かめること                                                                                                                                  |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| 機体が一覧に出ない         | backend が動いているか、同じ LAN か。mDNS が届かない網では [機体の登録](maintenance.md#%E6%A9%9F%E4%BD%93%E3%81%AE%E7%99%BB%E9%8C%B2) を行う  |
| 機体を選ぶと 503 になる    | backend のサービスと到達先。電源を切った機体が mDNS の一覧にしばらく残ることがある                                                            |
| ボタンが薄くて押せない     | 操作権の表示。読み込み中、閲覧者、別のジョブの実行中は、装置を動かす操作ができない                                                            |
| PCB ファイルが見つからない | 機体のファイルか、開ける場所か。frontend のホストに挿した USB メモリは見えない                                                                |
| ジョブが入力待ちのまま     | 画面の質問か手動操作のメニュー。入力待ち音は機体のスピーカーから鳴る                                                                          |
| 全ページに設定エラーが出る | `machine.toml` の誤り。[設定エラーから戻す](maintenance.md#%E8%A8%AD%E5%AE%9A%E3%82%A8%E3%83%A9%E3%83%BC%E3%81%8B%E3%82%89%E6%88%BB%E3%81%99) |
| 更新が断られる             | [保守ガイドの更新](maintenance.md#%E6%9B%B4%E6%96%B0%E3%81%99%E3%82%8B)                                                                       |

解決しないときは、ログ（[ログを見る](maintenance.md#%E3%83%AD%E3%82%B0%E3%82%92%E8%A6%8B%E3%82%8B)）と [不具合の報告に要るもの](develop/index.md#%E4%B8%8D%E5%85%B7%E5%90%88%E3%82%92%E5%A0%B1%E5%91%8A%E3%81%99%E3%82%8B) を添えて報告する。
