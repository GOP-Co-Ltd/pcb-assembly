# 実機受け入れ試験

[ドキュメント一覧](../README.md) · [保守ガイド](maintenance.md) · [開発の手引き](develop/index.md)

実機での確認はこの文書にだけ書く。pytest は実機に触れない（Klipper への接続と systemctl の呼び出しは、テスト中は必ず失敗する）。
送信する G-code の列は `tests/golden/` の golden で固定し、ここでは golden で見えないもの（機構の動き、カメラ、音、画面）を確かめる。

001 は `usaremino001`、002 は `usaremino002` を指す。

## merge 前の手順

### 1. 001 でブランチを確かめる

本番の config と data のまま、ブランチのコードで 001 を動かす。
確認の操作（教示、校正、Apply、即時書込）は本番の設定を書き換えるので、先に退避し、最後に戻す。

1. 設定と校正を退避し、本番のサービスを止める

    ```sh
    backup=~/acceptance-backup/$(date +%Y%m%d-%H%M%S)
    mkdir -p "$backup"
    cp -a ~/pcb-assembly/config ~/pcb-assembly/data/paste-volume-calibrations "$backup"/
    sudo systemctl stop pcbasm-ui pcbasm-api
    ```

2. worktree でブランチに切り替え、依存をそろえる

    ```sh
    cd ~/pcb-assembly/.claude/worktrees/<worktree>
    git switch <ブランチ>
    uv sync --locked --inexact  # worktree に .venv が無ければ make setup
    ```

3. 別々のターミナルで、config と data を本番に向けて起動する

    ```sh
    export PCBASM_CONFIG_DIR=$HOME/pcb-assembly/config PCBASM_DATA_DIR=$HOME/pcb-assembly/data
    make api  # もう一方のターミナルでも export してから make ui
    ```

4. 下の対応表から、変えた領域の項目を実施する。PR 本文に、実施した項目と対象機、ジャーナルの前後 diff を書く

5. 両方を Ctrl-C で止め、退避したときからの設定の変化を見る

    ```sh
    diff -ru "$backup/config" ~/pcb-assembly/config
    diff -ru "$backup/paste-volume-calibrations" ~/pcb-assembly/data/paste-volume-calibrations
    ```

    差分のうち、教示し直すと決めて取った値（キャップ位置など）でないものは、`$backup` のファイルから戻す。
    全部戻すなら `cp -a "$backup/config/." ~/pcb-assembly/config/` を実行する

6. 本番のサービスを戻し、本番の WebUI で本番の PCB を選び直す

    ```sh
    sudo systemctl start pcbasm-api pcbasm-ui
    ```

- 確認中にアップロード・選択した PCB は worktree の `uploads/` にあり、本番の選択（`data/webui/webui_state.json`）はそれを指したまま残る。worktree を消すと選択が外れるので、手順 6 で選び直す
- 確認中のファイルブラウザは worktree と `/media`、`/mnt` しか開けず、本番の `~/pcb-assembly/uploads` は開けない。本番の PCB を使うなら、確認の前に本番の WebUI で選んでおく
- この起動では active な unit が無いので、再起動（復旧）は Klipper だけを再起動し、WebUI のサービスは再起動しない。サービスの再起動まで含めた A14 は、merge 後に本番の unit で行う
- ジャーナル（`data/webui/journal/`）は本番と共有する。同じジョブを前の版とブランチで 1 回ずつ流し、2 つのファイルを diff する。前の版がジャーナルを持たない間は、golden を基準にする
- 運用データを書き換える PR（設定の移行、基板 override の付け替え、校正 JSON の形式変更）では、確認で本番のファイルが書き換わる。不合格なら、次の手動ロールバックで元に戻す

### 2. 002 は保留する

001 の受け入れが通るまで、002 は更新しない。
運用データを書き換える PR は、merge の前に両機を直前の版まで更新し、両機の `/api/update/status` の head を PR 本文に記録する。merge 後に 002 で A19 を行う。

### 3. 手動ロールバック

[保守ガイドの手動ロールバック](maintenance.md#%E6%89%8B%E5%8B%95%E3%83%AD%E3%83%BC%E3%83%AB%E3%83%90%E3%83%83%E3%82%AF) の手順で、前の head から復旧ブランチを作って戻す。
設定は `config/history/` の世代から戻す。
設定履歴を持たない古い版へ戻すときは、「1. 001 でブランチを確かめる」の手順 1 で退避したファイルから戻す。

### A0 装置診断

- 画面: 装置診断（`machine_check`）。機体タブの「状態と診断」にある
- 操作: 開始を押し、ログに並ぶ項目を読む。装置は動かない
- 合格条件: 全項目が ok でジョブが終わる。Klipper が ready で、printer.cfg の必須 section がそろい、カメラの校正に焦点 Z があって解像度が校正と一致し、`[audio]` の出力デバイスが ALSA に見える

### A1 装置操作

- 画面: マシン操作パネル、Klipper ステータス（`klipper_status`）
- 操作: 全軸ホーミング → X を +0.1 mm、-0.1 mm ジョグ → 可動域外への絶対移動 → Relax → ジョグ → G-code 送信（`M400`）
- 合格条件: ホーミング後の homed axes が `xyz`。ジョグの前後で位置表示が 0.01 mm 以内で一致する。可動域外の移動は 400 で、ステージは動かない。Relax の後のジョグは拒否される。G-code 送信が成功し、Stage Limits に各軸の min < max が出る

### A2 ノズルキャップとクリーニング

- 画面: ノズル位置の設定（`nozzle_cap`）、マシン操作パネルの「キャップ位置へ」
- 操作: ホーミング後にキャップ位置とクリーニング位置を記録する → クリーニングのテストを 2 回続けて押す → もう一度押して、ホーミング中に「中止」を押す → 塗布系のジョブを 1 つ終える → 全軸ホーミングする → 設定ページでクリーニング位置 X を可動域の max より大きくしてテストを押し、元の値に戻す
- 合格条件: 記録した位置が `config/machine.toml` の `[solder.nozzle.cap]` と `[solder.nozzle.clean]` に入る。テストはジョブとして走り、同じページにログが出る。こすりの後に TRAVEL_Z へ戻り、終了時にキャップへ駐機して脱力する。2 回目は脱力しているのでホーミングしてからクリーニングする。ホーミング中の中止ではパージせずにキャップへ駐機して「中止」で終わる。ジョブの終了時にキャップへ駐機する。可動域外の位置でのテストは「クリーニング位置が可動域外です」で失敗し、クリーニング位置へは動かず、パージも出ない（終了時の駐機だけ行う。脱力したまま押すと、キャップへの移動を Klipper が断り「タスク終了時の退避に失敗」が出る）

### A3 基準点の教示

- 画面: `reference_point_setup`
- 操作: ジョグ → record。もう一度開始して quit
- 合格条件: record で現在位置が設定に反映され（Apply は不要）、summary の x / y と設定ページの値が一致する。基準円がオーバーレイと合う。quit は中止になり、設定は変わらない

### A4 カメラ校正

- 画面: `camera_calibration`
- 前提: 1 マス 1.5 mm のチェッカーボードを視野に置く
- 合格条件: 結果の JSON に z_position が記録され、新しいファイル名で保存される（旧ファイルは残る）。Apply の後、再起動せずに次のジョブで新しい校正が使われる

### A5 基板の巡回と直交性

- 画面: `board_tour`、`orthogonality_test`
- 前提: 基準点マーカーが視野に入るように基板（例: `tests/data/fill_coverage`）を置き、その PCB を選ぶ
- 操作: board_tour を通す。orthogonality_test は各点の確認で「次へ」を押し、途中で「終了」を押す
- 合格条件: board_tour が成功し、summary に照合の残差が出る。orthogonality_test は確認を待つ間ずっと十字線・ROI・巡回先ラベルが出続け、「終了」で正常終了して summary に軸間角・巡回点数・周回数が出る。残差と軸間角が従来値と同程度である（前後の値を PR 本文に記録する）

### A6 ローディング

- 画面: `loading`
- 操作: 位置 X を指定して開始 → 押出 → 回転押出（引き戻しあり・なし）→ 負の量で押出 → ジョグ → 終了
- 合格条件: 開始時に全軸ホーミングしてから指定の X へ移動する。summary に押出合計 [uL] と回転合計 [rev]（押出から引き戻しを引いた純増）が出る。負の量は押し出さずに理由をログに出し、ループは続く。ループ内でジョグが効く

### A7 高さ平面

- 画面: `height_plane`
- 合格条件: プローブが通しで動き、計測予定点とヒートマップの画像が成果物に出る

### A8 はんだ塗布の通し

- 画面: `paste_solder`
- 前提: テスト基板（例: `tests/data/led_blinker`）をセットし、その PCB を選ぶ
- 操作: probe → 領域照合 → pad の精密照合 → 初回パージの撮影確認 → 塗布 → 駐機まで通す
- 合格条件: 塗布がパッドに乗り、キャップへ駐機して終わる。前の版とのジャーナルの diff に、意図しない差が無い

### A9 オフセットと吐出量・塗布量の校正

- 画面: `toolhead_offset`、`dispense_calibration`（①）、`paste_volume_calibration`（小さい格子）
- 合格条件: それぞれ値が保存され、Apply の後に設定ページの値と一致する

### A10 通知音、プレビュー、設定の保存

- 画面: 通知音（`audio`）、カメラプレビュー（`camera_preview`）、マシン設定
- 合格条件: 選んだデバイスで音が鳴る。プレビューが動く。設定を保存した後も `machine.toml` のコメントが残り、`config/history/` にスナップショットができる

### A11 自己更新

- 画面: ソフトウェア更新（`/update`）、機体一覧
- 合格条件: 001 と 002 の両方で WebUI から更新できる。版のずれた機体が「更新専用」で見える。unit drift の警告が誤って出ない

### A12 複数機体

- 画面: 機体一覧、機体の切替
- 合格条件: 機体一覧から切り替えられる。操作権が機体ごとに独立している。更新専用の機体でも緊急停止できる

### A13 設定エラーからの復旧

- 操作: `machine.toml` をわざと壊して backend を起動する（値の誤り、例: `lift_height = 0`。書式の誤り、例: 閉じていない文字列）
- 合格条件: backend が起動し、機体一覧に載る。全ページに設定エラーの理由が出て、ジョブの開始は断られる。緊急停止が効く。値の誤りは設定画面から、書式の誤りは設定履歴の復元から直せ、バックアップも取れる。直すと再起動なしで理由の表示が消える

### A14 移動中の緊急停止と復旧

- 操作: 長い移動（例: 可動域の端から端への絶対移動）の途中で緊急停止を押す → 再起動（復旧）を押す
- 合格条件: 緊急停止ですぐ止まり、実行中のジョブは中止になる。再起動（復旧）の後、ssh などの手当てなしに画面が戻り、ホーミングから操作を再開できる

### A15 クリーニング分岐の強制

- 操作: 初回パージ量（`initial_purge_ul`）を検出の下限より小さくして `paste_solder` を開始する
- 合格条件: パージが写らず、ノズルクリーニング → やり直しの経路を通る。終わったら初回パージ量を元に戻す

### A16 校正の残り

- 画面: `dispense_calibration`（②③）、`paste_volume_refit`、`paste_dataset_finalize`
- 合格条件: ②③が値を保存する。refit が保存済みのデータセットから校正を作り直す。収集を途中で止めてできた `.incomplete` を、finalize で確定できる

### A17 基板とプレビュー

- 画面: `paste_solder` の PCB 選択と pad editor
- 操作: PCB をアップロードし、USB メモリ（`/media`）の PCB も開く。pad editor で export → import する。route / fill-path / copper / initial-purge のプレビューを出す。pad を変えた基板を同じ名前で再アップロードする
- 合格条件: どの操作もエラーにならない。再アップロードの後、新しい pad が表に出て、塗布できる

### A18 Apply と即時書込

- 対象: solder.dispenser.rotations_per_ul、solder.dispenser.max_dispense_rate、solder.motion.max_fill_speed、solder.initial_purge_ul、solder.nozzle.offset、reference_point、camera.calibration_file、alignment.canny_low
- 合格条件: どれも書込が成功し、設定ページの値と一致する

### A19 002 での確認

- 対象: 運用データを書き換える PR（設定の移行、基板 override の付け替え、校正 JSON の形式変更）
- 合格条件: 002 で、設定ページの値が更新前と一致し、1 回塗布できる

### A20 電源の入れ直し

- 操作: Pi の電源を入れ直す
- 合格条件: Moonraker の起動が遅れても、操作なしで使える状態へ戻る

### A21 所要時間の予測と実測

- 画面: `paste_solder`
- 前提: A8 と同じ基板と PCB。起動時の移行で `machine.toml` の `[tact]` から `travel_speed` / `travel_accel` / `z_speed` / `z_accel` が消え、`[solder.tact]` から `setup_sec` が消えている（`config/history/machine-pre-O.toml` が残る）
- 操作: 実行前に予測所要時間と前段の内訳を控え、A8 の塗布を通す。終わったらジョブコンソールの経過と見比べ、ずれが大きければ `solder.tact` の値を合わせる
- 合格条件: パッドを無効にすると予測が短くなる。予測と経過の差が 1 割以内に収まる（ずれたら `solder.tact` を合わせた後に）

### A22 機体の機能と [solder] への移行

- 前提: 移行前の `machine.toml`（`[paste_dispenser]` と `[tact]` の形）で、設定ページの全値を控えておく
- 操作: ブランチで backend を起動する
- 合格条件: `machine.toml` が `[solder]` の階層（`dispenser` / `nozzle` / `motion` / `defaults` / `auto` / `volume_correction` / `tact`）に移り、`config/history/machine-pre-N.toml` が残る。設定ページの全値が控えと一致する。機体一覧に「はんだ塗布」のバッジが出る。タブ（塗布 / 校正 / 基板 / 機体）、着地点（`paste_solder`）、塗布の画面が移行前と同じで、A8 と A18 が通る

### A23 ピンセットのサーボ設定

- 画面: `servo_setup`（PnP 機の校正タブ）
- 前提: 2 台のサーボが別々の ID を持つ（モードはどちらでもよい。取り付けたばかりの位置モードのままでよい）。`machine.toml` の `[pnp.servo]` に `port` を書いてある。始める前にピンセットを中ほど（閉じ切り・開き切りでない位置）にしておく（判別の振りで当たりに押し付けないため）
- 操作: ジョブを始め、振られたサーボの役割を 1 台ずつ選ぶ。Open Close のトルクが切れたら、手で閉じ切り・開き切りにして「読む」を押す。ピンセットから手を離して「動かす」を押し、確認の開閉を見て「はい」を押し、Apply する
- 合格条件:
    - 役割を尋ねる前に振る動き（既定 ±5°。フォームの「判別で振る角度」で変えられる）で、どちらのサーボか見分けられ、振った後は元の向き・位置に戻る
    - 役割はボタンで選べ、「もう一度動かす」は役割のボタンとは別の段にある
    - 確認の開閉で、閉じ切り・開き切りの当たりで唸らない（唸るなら「やり直す」で読み直せる）
    - 確認の開閉が当たりに押し付けて止まりきらないときは、トルクが切れ、ログに出て閉じ切り・開き切りの読み直しに戻る
    - ジョブが終わると（成功・中止・失敗のどれでも）、2 台とも脱力して手で回せる
    - Apply の後、`[pnp.servo]` の `rotation_id` / `open_close_id` / `closed_angle` / `open_angle`（角度 [°]） が summary の 4 値と一致する
    - 確認の開閉の前に、Open Close の角度制限（EEPROM の MIN / MAX_ANGLE_LIMIT）が閉じ切り〜開き切りに書かれ、ログに出る。Apply の後、設定ページで開き切りの角度を広げても、サーボ（WebUI のピンセット操作や FD ツールの指令）は開き切りの外へ動かない
    - 範囲を読み直す（「やり直す」）と、前回の制限を外してから読むので、前回より広い範囲も読める
    - 役割を選ぶと、役割とモードが合わないサーボにジョブがモードを書き（Rotation は 3、Open Close は 0）、ログに出る。電源を入れ直してもモードが残る
    - Rotation（ステップモード）の振りの向きと量が指令どおり（既定の 5° なら + で一方へ 5°、- で逆へ 10°、+ で戻る。負の step の sign-magnitude を確かめる）
    - Rotation の角度制限が 0 / 0（制限なし）に書かれる。ステップモードでも制限があると、同じ向きに回し続けたときに端で止まる（A25 の連続回転で確かめる）

### A24 サーボ脱力

- 画面: マシン操作パネル（PnP 機）
- 前提: `machine.toml` の `[pnp.servo]` に `port` を書いてある。サーボのトルクが入っている（A23 の後など）
- 操作: 操作権を取り、パネルの「サーボ脱力」を押す
- 合格条件: 2 台ともトルクが切れて手で回せる（`[pnp.servo]` の役割を設定する前でも切れる）。塗布機のパネルには「サーボ脱力」が出ない。ジョブの実行中は押せない

### A25 ピンセットのパネル操作

- 画面: マシン操作パネルのピンセット欄（PnP 機）
- 前提: A23 を済ませ、`[pnp.servo]` に役割と閉じ切り・開き切りの角度がある（角度制限を書く前の古いサーボ設定ジョブで作った設定なら、ジョブをやり直す）
- 操作:
    1. 操作権を取り、Rotation の ±1・±10・±90° を押す
    2. +90° を 10 回以上（3 回転ぶん）押し続け、続けて -90° を同じだけ押す
    3. `[pnp.servo] rotation_speed` を変えて保存し、±90° をもう一度押す
    4. Open Close のスライダーをゆっくり動かし続けてから離す。数値欄に 0 と 1 を入れて Enter を押す
    5. 部品をつまんだ（Open Close を 0 にした）まま、Rotation の ± を押す
    6. 「サーボ脱力」を押し、パネルを開いたまま数秒待つ
- 合格条件:
    - 1: 押した向きと角度だけ回る（+ と - で逆向き）
    - 2: どちらの向きにも、途中で止まらずに回り続ける
    - 3: 回る速さが設定に従って変わる
    - 4: スライダーを動かしている間、離すのを待たずにピンセットが追従する。0 で閉じ切り、1 で開き切りまで動き、開き切りの先へは回らない。0 を送ると欄は 0 を表示し、実測の開き具合は「現在」として別に出る
    - 5: 回している間も部品を落とさない（つまむ力が抜けない）
    - 6: 2 台とも手で回せるまま（今の値の表示でトルクが入らない）
    - 角度制限が古いままのサーボ（設定ジョブをやり直す前）では、操作が「サーボ設定ジョブをやり直してください」のエラーになる
    - 塗布機のパネルにはピンセット欄が出ない

### A26 Xbox コントローラの入力

- 前提: Xbox コントローラを Pi に USB でつなぐ（Bluetooth でも試すなら、ペアリングしておく。Xbox コントローラは Bluetooth で使う前にファームウェアを最新にしておく）。実行するユーザーが `input` グループに入っている（`/dev/input/event*` を読むため。`id` で確かめる）。WebUI のサービスとは別のターミナルで行う

- 操作: 次を実行し、LT をゆっくり押し込んで離す、LB と RB を 1 つずつ押して離す。左スティックを上・下・左・右に倒し切ってから離す。右スティックを上・下に倒し切ってから離し、続けて左右に倒す。Ctrl-C で止める。Bluetooth でつないだコントローラでも同じことをする

    ```sh
    uv run python -c "
    import time
    from pcbasm.hal.gamepad import open_gamepad
    pad = open_gamepad()
    while True:
        print(pad.state(), end='\r'); time.sleep(0.02)
    "
    ```

- 合格条件:

    - LT が離すと 0.0、押し込むと 1.0 になり、途中は押し込みに応じて連続して変わる（USB と Bluetooth のどちらでも）
    - LB を押している間だけ `left_bumper=True`、RB を押している間だけ `right_bumper=True` になる。スティック・RT・ほかのボタンでは LT・LB・RB が変わらない
    - 左スティックを右に倒すと `left_x` が 1.0 付近、左で -1.0 付近、上に倒すと `left_y` が 1.0 付近、下で -1.0 付近になる。右スティックを上に倒すと `right_y` が 1.0 付近、下で -1.0 付近になる（USB と Bluetooth のどちらでも。Bluetooth の `hid-microsoft` では右スティックの縦が `ABS_RZ` に載る）。右スティックを左右に倒しても `right_y` はほとんど変わらない
    - スティックを離すと、各値が 0 付近に戻る。戻りきらずに残る値（たとえば 0.02）を、USB と Bluetooth のそれぞれで PR 本文に書く（デッドゾーンの既定 0.15 が足りるかの根拠にする）
    - 実行中にケーブルを抜く（Bluetooth なら電源を切る）と `GamepadError`（切断されました）で止まる

### A27 コントローラでピンセット操作

- 画面: マシン操作パネルの「コントローラ操作」（Klipper の PnP 機。ジョブ `gamepad_control`）
- 前提: A25 と A26 を済ませ、Xbox コントローラを Pi につないである
- 操作:
    1. ジョブを始め、LT をゆっくり押し込んでから離す
    2. RB を数秒押し続けて離す。LB でも同じことをする。続けて、RB を 3 回転ぶん以上押し続ける
    3. LB と RB を同時に押す
    4. 部品をつまんだ（LT を離した）まま RB を押す
    5. RB を押したまま、「コントローラ操作を終える」を押す
    6. もう一度ジョブを始め、RB を押したままコントローラのケーブルを抜く（Bluetooth なら電源を切る）
- 合格条件:
    - 1: 押し込むほどピンセットが開き、押し込み切ると開き切り、離すと閉じ切りまで戻る。動きがトリガーに遅れずに付いてくる
    - 2: 押している間だけ、`[pnp.servo] rotation_speed` の速さで途切れずに回り続け、離すとすぐ止まる（行き過ぎて戻らない。45°/s なら止まるまで数度）。RB と LB で向きが逆。何回転しても止まらない
    - 3: 回転が止まる
    - 4: 回している間も部品を落とさない
    - 5: ジョブが中止で終わり、回転が止まり、ピンセットはトルクが入ったまま（つまんだ部品を落とさない）。パネルの操作がまた使える
    - 6: ジョブが「切断」のエラーで終わり、回転が止まる（Bluetooth はカーネルが切断に気づくまで数秒回り続けることがある）

### A28 新ファームのステージへの接続

- 画面: マシン操作パネルと `klipper_status`（PnP 機の機体タブ）
- 前提:
    - MCU に pnp-motion ファームを書き込んである（`./install.sh firmware pnp-motion`）
    - Klipper のサービスを止めて無効にしてある（`sudo systemctl disable --now klipper`）。Klipper が同じシリアルを開いていると話せない
    - `machine.toml` に `[pnp.motion]` を書き、`[klipper]` を消してある（雛形は `deploy/templates/kurousagi/machine.toml`）。`serial` は `ls /dev/serial/by-id/` で確かめる
- 操作:
    1. backend を起動し、`klipper_status` を開く
    2. マシン操作パネルを開く
    3. `serial` を Klipper のファームを書いた MCU（または存在しないデバイス）に向けて、操作パネルの Home を押す
- 合格条件:
    - 1: 接続状態と可動域（`[pnp.motion]` の `position_min`〜`position_max`）が出る。G-code の入力欄が出ない
    - 2: Z のボタンは + が上に並ぶ。焦点 Z とキャップ位置へのボタンが出ない。サイドバーに Klipper（Mainsail）へのリンクが出ない
    - 接続の際に、TMC2209 の確認（IFCNT と GCONF の読み戻し）で失敗しない。失敗すると操作がエラーになり、文言に IFCNT が出る
    - 3: 「pnp-motion ファームではありません。`./install.sh firmware pnp-motion` で書き込んでください」か、開けない旨のエラーになり、機械は動かない

### A29 原点出しとパネルの位置操作

- 画面: マシン操作パネル（PnP 機）
- 前提: A28 を済ませる。ノズルが周りに引っかからない位置にある
- 操作:
    1. 操作権を取り、原点出しの前に位置の表示を見る。続けて XY のジョグを押す
    2. X だけの Home を押す（Z の原点が未のまま）
    3. 全軸の Home を押す
    4. X・Y・Z のそれぞれで ±0.1・±1・±10 のジョグを押す
    5. 座標を入れて移動する。行き先を定規やカメラの映像で測る
    6. 可動域の端（`position_min`、`position_max`）へ移動する。端の外へのジョグと移動も押す
    7. Relax を押す
    8. 全軸の原点を出し、コントローラ操作のジョブを止めた状態で、何も操作せずに 5 分（`[pnp.motion]` の `idle_timeout` の既定）待つ
- 合格条件:
    - 1: 位置が `X? Y? Z?` と出る。ジョグは「原点出しをしていない軸」のエラーになり、動かない
    - 2: Z の原点を先に出してから X を出す（ノズルが引っかからない）
    - 3: Z → X → Y の順に、1 回目は速くスイッチに当たり、離れてから 2 回目はゆっくり当たる。終わると位置が `position_endstop` の値になる
    - 4: 押した軸だけが押した向きと距離だけ動く。Z は上のボタン（+）で Z+ に動く（ステージが下がり、ピンセットから離れる）。位置の表示が動いた量と一致する
    - 5: 測った位置が入れた座標と一致し、位置の表示とも一致する。XY を同時に変えると直線に動く
    - 6: 端の手前で減速して端で止まり、機構の当たりやスイッチに当たらない。端の外への操作は「可動域の外」のエラーになり、動かない
    - 7: XYZ のモーターが脱力し、手で動かせる。位置が `X? Y? Z?` に戻る。Relax の後に何もしなければ、励磁は入り直さない
    - 8: 5 分を過ぎると（5 分 1 秒までに）ファームが XYZ のモーターを脱力し、位置が `X? Y? Z?` に戻る。ジョグは「原点出しをしていない軸」のエラーになる。
        5 分より前にジョグや移動をすると、そこから数え直す

### A30 新ファームの緊急停止と再起動

- 画面: マシン操作パネルとヘッダの緊急停止・再起動（復旧）（PnP 機）
- 前提: A29 を済ませる
- 操作:
    1. 全軸の原点を出し、可動域の端から端への長い移動を始め、途中で緊急停止を押す
    2. `klipper_status` で状態を見て、パネルの操作を押す
    3. 再起動（復旧）を押す
    4. `machine.toml` の `[pnp.motion]` の値（たとえば `max_velocity`）を変えて保存し、再起動（復旧）を押してから移動する
    5. backend を起動し直した直後（パネルで何も操作していない状態）に、緊急停止を押す
- 合格条件:
    - 1: すぐに止まる（減速を待たない）。shutdown で励磁が切れたときに、Z が自重で落ちない（落ちるなら、落ちた量を PR 本文に書く）
    - 2: 接続が切れた表示に shutdown の理由が出る。操作はエラーになり、機械は動かない
    - 3: 「XYZ の MCU を再起動しました。原点は「未」に戻ったので、原点出しからやり直してください。」と出る。WebUI のサービスは再起動しない（ページを開き直さずに操作を続けられる）。位置が `X? Y? Z?` に戻り、原点出しからやり直すと A29 のとおりに動く
    - 4: 変えた値が効く（再起動の前は、`machine.toml` を書き換えても開いているステージは古い値のまま）
    - 5: MCU が shutdown する（緊急停止のためだけに開いて送る）

### A31 backend の停止と再起動

- 画面: マシン操作パネル（PnP 機）
- 前提: A29 を済ませる
- 操作:
    1. 全軸の原点を出し、可動域の端から端への長い移動を始め、途中で backend を `kill -9` する
    2. backend を起動し直し、`klipper_status` を開いてから、パネルの Home を押す

### A32 コントローラで XYZ 操作

- 画面: マシン操作パネルの「コントローラ操作」（新ファームの PnP 機。ジョブ `gamepad_motion`）
- 前提: A26 と A29 を済ませ、Xbox コントローラを Pi につないである。ピンセットも試すなら A27 も済ませる。全軸の原点を出し、ノズルが周りに引っかからない位置にある
- 操作:
    1. ジョブを始め、左スティックを上・下・左・右にゆっくり倒す。続けて右スティックを上・下にゆっくり倒す
    2. スティックを倒し切って数秒動かし、離す
    3. 両方のスティックから手を離し、10 秒待つ
    4. 設定ページの「コントローラ」で `deadzone_xy` と `deadzone_z` を 0 にして保存し、ジョブを始め直して 3 をくり返す。続けて 0.3 にして、スティックを少しだけ倒す
    5. 左スティックで XY を動かしながら、LT を押し込んで離す。LB・RB も押す
    6. Bluetooth でつないだコントローラで、1 の右スティックの上下をくり返す
    7. Relax を押して原点を「未」にしてから、ジョブを始め直してスティックを倒す
    8. 左スティックを倒したまま、コントローラのケーブルを抜く（Bluetooth なら電源を切る）。続けて画面の仮想スティック（A33）を操作する
    9. 左スティックを倒したまま、「コントローラ操作を終える」を押す
    10. 左スティックを倒したまま、backend を `kill -9` する
- 合格条件:
    - 1: 左スティックの上で Y− に、右で X+ に動く（パネルのジョグの上・右と同じ向き）。右スティックの上で Z+ に動く（ステージが下がり、ピンセットから離れる）。倒す量に応じて速さが連続して変わり、デッドゾーンの縁で急に動き出さない
    - 2: 倒し切ると `[pnp.motion]` の各軸の `max_velocity` で動き、可動域の端の手前で減速して止まる。離すとすぐ止まる
    - 3: どの軸も動かない（漂わない）。位置の表示も変わらない
    - 4: 0 にすると、手を離した状態で漂う軸があれば分かる（漂ったら、その軸と量を PR 本文に書く）。0.3 にすると、少しだけ倒しても動かず、0.15 のときより大きく倒して動き出す
    - 5: XY が止まらずに動き続けたまま、ピンセットが LT に付いて開閉し、LB・RB で回る。XY の動きもピンセットの動きも、もう一方を操作したことで遅れたり途切れたりしない
    - 6: Bluetooth でも右スティックの上で Z+（ステージが下がる）、下で Z−（ステージが上がる）に動く。右スティックの左右では Z が動かない
    - 7: 原点が未の軸は動かず、ジョブはエラーにならない。backend のログに「原点出しをしていない軸はスティックで動かしません」が 1 回だけ出る
    - 8: XYZ がすぐ止まる。ジョブは終わらず、backend のログに「コントローラが外れました」が出る。仮想スティックでは動かせる
    - 9: ジョブが中止で終わり、XYZ が止まる。回転も止まり、ピンセットはトルクが入ったまま
    - 10: backend が止まってすぐ（速度指令の期限の 0.2 s のうちに）止まる。起動し直すと、原点は「未」から始まる（A31 と同じ）

### A33 画面の仮想スティック

- 画面: マシン操作パネルの「コントローラ操作」の下にある仮想スティック（新ファームの PnP 機。XY のパッドと Z のスライダー）
- 前提: A29 を済ませ、全軸の原点を出してある。コントローラはつないでも、つながなくてもよい（両方で行う）。スマートフォンやタブレットのブラウザでも試す
- 操作:
    1. コントローラをつながずにジョブを始める
    2. XY のパッドのつまみを押したまま、上・右・斜めに動かして離す。パッドの外まで引いてから離す
    3. Z のスライダーを押したまま上下に動かして離す
    4. パッドを押したまま、ブラウザのタブを閉じる。別のタブで同じことを、タブを切り替えて（画面を隠して）行う
    5. パッドを押したまま、Pi と PC の間の LAN ケーブルを抜く（Wi-Fi なら切る）
    6. コントローラをつないで左スティックを倒したまま、パッドを押す
    7. 操作権を持たない別のブラウザから、パッドを押す
- 合格条件:
    - 1: backend のログに「コントローラがありません」が出て、ジョブは続く（ボタンは「コントローラ操作を終える」のまま）
    - 2: つまみの上で Y−、右で X+ に動き、パッドの縁で各軸の `max_velocity` になる（デッドゾーンは掛からない）。パッドの外に引いても、つまみは縁で止まり、速さは縁のときと同じ。離すとすぐ止まり、つまみは中央に戻る
    - 3: 上で Z+（ステージが下がる）、下で Z−（ステージが上がる）に動く。離すとすぐ止まる
    - 4: どちらも 0.3 s のうちに止まる
    - 5: 0.3 s のうちに止まる（ジョブは続く）
    - 6: 押している間は仮想スティックの向きに動き、離すと左スティックの向きに戻る
    - 7: 動かない（操作権が無い旨が出る）
    - スマートフォンでパッドを動かしても、ページがスクロールしたり拡大したりしない

### A34 LED とロードセルの読み取り

- 画面: マシン操作パネルの荷重の行と TARE ボタン（PnP 機）。backend のログ（`journalctl -u pcbasm-api -f`）
- 前提: A29 を済ませ、`machine.toml` の `[pnp.motion]` に `led_pin` と `[pnp.motion.load_cell]` を書いてある。Klipper / Moonraker は止めてある（MCU を同時に開かない）
- ログ: Z が止まっている区間と動いている区間（Z の指令から 1 s まで）が切り替わるたびに、その区間の荷重の最小と最大が `ロードセルの荷重（Z が動いていた 3.2 s）: 最小 -1.20 g、最大 2.05 g` の形で出る。パネルの荷重は 2 s ごとに最後の 1 サンプルを出すだけなので、一瞬の値はこのログで読む。荷重は自動のタール（Z が止まって約 2 s 後から、およそ 1 s ごとに取り直す）からの差
- 操作:
    1. backend を起動し、`klipper_status` を開いてパネルの Home を押す。続けて緊急停止、再起動（復旧）、backend の停止と起動を順に行う
    2. パネルの Home を押し、何にも触れずに Z を止めたまま 10 秒以上待つ。次に Z を少し（パネルの Z の ±0.1）動かし、ログの「Z が止まっていた」の行の最小と最大を読む
    3. ステージを、指で軽く押す。ロードセルはステージそのものに付いていて、押すと荷重が増える
    4. 重さの分かるおもり（たとえば 20 g）をステージに載せ、パネルの荷重を読む。載せている間は Z を動かさない
    5. 何も触れずに Z を可動域の端から端まで `max_velocity` で往復させ（パネルの Z の ±10 を続けて押すか、コントローラの右スティックを倒し切る）、止めてから 1 s 後に出るログの「Z が動いていた」の行の最小と最大を読む
    6. 何かを載せたまま TARE を押す。そのまま 30 分置き、パネルの荷重を読む
- 合格条件:
    - 1: LED が起動してから消えない。緊急停止（shutdown）と backend の停止の間も点いたまま。再起動（復旧）と、設定を変えた後やこの版で最初に接続したときは、MCU の reset から設定し直すまでの一瞬だけ消える（reset の間はファームが動いていないので、ファームを変えない限り避けられない）
    - 2: 最小と最大の幅（Z を止めている間の、自動のタール値との差の揺れ）が 0.5 g（自動のタールの安定の幅）より小さい。幅を PR 本文に書く。広ければ自動のタールが効かないので、`load_cell.py` の `_TARE_SPREAD` を見直す。温度などのゆっくりしたずれは自動のタールが追うので、この幅には出ない
    - 3: 正の g になる。負なら `sensor_orientation` を `inverted` にする
    - 4: おもりの重さとおおむね合う（`counts_per_gram` の確認）。ずれた割合を PR 本文に書く。Z がピンセットから離れた範囲（Home の直後）にあれば、載せたまま約 2 s で自動のタールに取り込まれて 0 g に戻る（A35）。範囲の外では 2 g（`_TARE_DRIFT`）より大きい差を取り込まないので、0 g には戻らない
    - 5: 最大と最小を PR 本文に書く（接触の判定のしきい値を決めるときの、加速度で出る見かけの荷重）
    - 6: TARE で 0.0 g になる。30 分後も 0 g 付近（自動のタールが温度のずれを追う）。ずれを PR 本文に書く
    - 誤り: HX711 の配線を抜くと「ロードセル: ロードセルの値が来ない」か「HX711 の読み出しが乱れた」が出て、挿し直すと荷重に戻る

### A35 ロードセルの接触停止と保持

- 画面: マシン操作パネルの荷重の行（「（接触中）」）、`gamepad_motion`（PnP 機）。backend のログ
- 前提: A34 を済ませ、`[pnp.motion.load_cell]` を書いてある。全軸の原点を出してある。Z の `max_velocity` は 10 mm/s（kurousagi の雛形の値）。
    向き: ステージが上がる Z− でピンセットに押し当たり、ステージが下がる Z+ で離れる（`press_positive = false`）
- 操作:
    1. 何も触れずに、Z を可動域の端から端まで `max_velocity`（10 mm/s）で往復させる。続けて `max_velocity` を一時的に 50 mm/s にして同じことをする
    2. 部品の載っていない基板をステージに置き、Z− にゆっくり（1 mm/s）動かしてピンセットに当てる。止まった位置を読む。続けて 10 mm/s と、試せるなら 50 mm/s で同じことをする
    3. 接触して止まったまま、左スティックの XY、右スティックの Z−（押す向き）、パネルの X のジョグ、Home、TARE を順に試す
    4. 右スティックの Z+ で離す
    5. XY を速く動かしている間に、ステージを指で軽くはじく
    6. X の原点出しの途中で、ステージを手で押す。続けて Z+ で離し、もう一度 X の原点を出す
    7. `gamepad_motion` のジョブで、左スティックで XY を動かしている間に、HX711 のデータ出力（`dout_pin`）の線を抜く。挿し直し、ジョブを開き直す
    8. 接触したまま 10 秒置き、離す
    9. `gamepad_motion` のジョブで XY を動かした後、スティックを離して止め、ステージを指で 50 g を超えるくらいに押す。指を離し、XY を動かす
    10. Home の直後（Z が離れた範囲にある）に、基板かおもりをステージに載せる（`trigger_force` の 50 g 未満で、たとえば 30 g）。Z は動かさず、パネルの荷重を 5 s 読む。続けて、載せたままで Z をゆっくり押す向きに動かす
    11. 載せたものを外し、Z を `free_tare_zone`（5 mm）より押す向きへ動かして止める（Z が −5 より小さい）。同じ 30 g を載せ、パネルの荷重を 5 s 読む。外して TARE を押す
    12. 位置を Z = −5（`free_tare_zone` の端）にして、ステージの上に基板などを載せずに、ステージがピンセットに触れないことを目で見て確かめる。触れるなら `free_tare_zone` を小さくする
- 合格条件:
    - 1: 10 mm/s では止まらない。A34 で読んだ見かけの荷重のピークと、しきい値（50 g）との差を PR 本文に書く。50 mm/s で止まったかも書く
    - 2: どの速さでも止まり、荷重の行に「（接触中）」が出る。1 mm/s で止まった位置を接触を始めた位置として、10 mm/s・50 mm/s で止まった位置との差（押し込み量）を PR 本文に書く。見積もりは 10 mm/s で 0.13〜0.25 mm、50 mm/s で 0.6〜1.25 mm
    - 3: どれも動かない。ジョグと Home と TARE は「接触中は…」の理由が出る。スティックの操作でジョブは終わらない
    - 4: Z+ にだけ動き、荷重が 15 g（`release_force`）を下回ると「（接触中）」が消え、XY も動かせる。XY を倒したまま離すと、その時点で XY が動き出す（体感を PR 本文に書く）
    - 5: 一瞬止まり、指を離すとすぐ動かせる（離すまで XY は止まったまま）
    - 6: 止まって「原点出しの途中で接触して止まった（X）」が出る。X は「未」のまま。Z+ で離した後に出し直せる
    - 7: 異常として止まり、ジョブが中止で終わって「ロードセルの異常で止めた（MONITOR）」などの理由が出る（「（接触中）」にはならない）。挿し直してジョブを開き直すと荷重に戻り、また動かせる
    - 8: 接触している間は自動のタールが取り直されない。離すと荷重が 0 g 付近に戻る
    - 10: 載せて約 2 s で荷重が 0 g 付近に戻る（タールに取り込まれる）。載せたまま Z を押す向きに動かしても、接触で止まらず、動き出す前の荷重は 0 g 付近
    - 11: 荷重は 30 g のまま 0 g に戻らない（範囲の外では取り込まない）。外すと −30 g になり、TARE で 0 g に戻る
    - 12: Z = −5 でステージがピンセットに触れない。`free_tare_zone` の範囲では、ピンセットに触れたことを自動のタールが取り込んでしまうため
    - 9: 止まっている間は押しても「（接触中）」にならず、指を離すとすぐ XY が動く（接触停止は動かしている間だけ張る）
- 保持から抜けられないとき: 離しても荷重が 15 g を下回らず「（接触中）」が消えないときは、タール値が押す側にずれている（引っかかった状態でタールしたときなど）。
    保持の間はタールを受け付けないので、脱力 → 何も触れていない状態で TARE → 原点出し、の順で戻す。起きたら、そのときの荷重と状況を PR 本文に書く

### A36 ロードセルの校正

- 画面: 校正タブの「ピンセット」の並びにあるロードセルの校正（`load_cell_calibrate`）。マシン操作パネルの荷重の行と「再起動（復旧）」。設定ページの部品実装の「ロードセル」
- 前提: A34 を済ませ、`[pnp.motion.load_cell]` を書いてある。重さの分かるおもりを 2 つ（たとえば 50 g と 100 g）用意する。接触保持の間（荷重の行に「（接触中）」）ではない
- 操作:
    1. ジョブを開始し、ステージに何も載せず、ピンセットにも触れさせずに「タール」を押す。50 g のおもりをステージに載せ、揺れが収まったら「測る」を押し、50 を入力する
    2. 同じおもりでもう一度ジョブを行い、算出値を 1 と比べる。続けて 100 g のおもりで行う
    3. 100 g の結果を Apply し、設定ページの「ロードセルの感度」を見る。マシン操作パネルの「再起動（復旧）」を押し、原点を出し直してから、TARE → 50 g のおもりを載せて荷重の行を読む
    4. 1 g のおもりで 1 を行う。続けて 0.3 g ほどの小さなもので 1 を行う。どちらも、載せてから「測る」を押すまで 5 s ほど置く
    5. おもりの代わりに、止めたまま指でステージを押して測る（30 g ほど）
- 合格条件:
    - 1: ログに `counts_per_gram` と、今の値との比が出る。kurousagi の Klipper の校正値（2666.98）と数 % 以内で合う。ずれた割合を PR 本文に書く
    - 2: 同じおもりの 2 回、50 g と 100 g の値が、それぞれ 1 % 以内でそろう。そろわなければ、A34 の 2 で読んだ止まっている間の揺れと並べて PR 本文に書く
    - 3: Apply の後、設定ページの値が算出値になる。再起動（復旧）の前は荷重の表示が古い値のまま、後は 50 g のおもりで 50 g 付近（1 % 以内）を示す
    - 4: 1 g は通る（約 2667 counts。1000 counts 以上）。置いている間も自動のタールに取り込まれない（ジョブの間は止めている）。0.3 g（約 800 counts）は「重さの差が小さすぎて校正できません」が出て、載せるところからやり直しになる（1000 counts は kurousagi で約 0.4 g）。ジョブを終えると自動のタールが戻り、操作パネルで載せたままの 1 g が 2 s ほどで 0 に戻る
    - 5: 測れる。ただし、Z を動かしている間に `trigger_force`（50 g）を超えると接触停止で止まる。押し当てる校正は止めたまま 50 g 未満で行い、それより重い荷重はおもりで与える
    - 向き: ステージにおもりを載せると差は押す向き（正）になり、ログに「差が負」は出ない。負と出たら `sensor_orientation` が逆なので、`inverted` を足して（外して）やり直す。値は絶対値で求まるので、負でも `counts_per_gram` は同じになる。向きを PR 本文に書く

## 未確認の項目（実機で確かめる）

既に main にある変更のうち、実機での確認が済んでいないもの。確かめたら、ここから消す。

- 静定待ちと検出サンプリング（`[settle]`、`[detection]`）
    - `settle.move_sec = 0.5` で、基準点移動とツールヘッドオフセットの静定が足りるか（以前は 1.0 s）
    - `detection.minimum_sample_count = 5` で、観測が失敗しないか（以前は 1）
    - `detection.sample_count = 10` で、位置合わせの再現性が落ちていないか（以前は 30）。INFO ログの有効検出数と標準偏差 X・Y で見る
- 微小線塗布（`micro_line`）
    - 始点の欠けと終点の過多が解消するか
    - `micro_line_z_start` / `micro_line_z_end`（既定は始点が自動、終点は始点に従う `start`）と `micro_line_settle_seconds`（既定 0.1 s）の値が合っているか
    - 最大速度で下降してもドームが崩れないか
- 終点高の既定を「始点に従う」に変えた: `micro_line_z_start` を数値にし `micro_line_z_end` を書いていない機体は、終点の Z が従来の auto 計算値から始点高の値に変わる。終点過多・始点欠けへの影響を見る
- 設定表の auto の高さの表示（選択欄の横の `(X)`。auto と、終点高の「始点に従う」）が、実際に塗るときのノズル高さと一致するか。G-code ジャーナルの Z と照らす
- 外周余白（`boundary_margin`）を負にしたとき、狙いどおりにはみ出して塗れるか。塗布量は pad 面積から決まるので、広げた経路では薄くなる。塗布量を増やすかは未決
- 大径側の外挿: 運転時の流量補正で、過吐出ぎみの `amount_ul` の点が採用されるか。`diameter_above_extrapolation_range` で外れた件数
- 塗布後の静定（`post_dispense_settle_seconds`、既定 0.1 s）で足りるか。流量キャリブレーションと塗布量校正を取り直す必要があるか
- 流量キャリブレーションの許容倍率（`solder.volume_correction.max_correction_scale`、既定 2.0。以前は 1/3〜3 倍で頭打ちして塗っていた）: 正常な状態の塗布ジョブが止まらないか。止まったら、ジョブログの補正前後の `rotations_per_ul` を見て、吐出量キャリブレーションをやり直すと通るか
- 塗布順序（設定表の「塗布順序」列）: 部品や pad の行に書いた順序どおりに、プレビューの番号と実際の塗布の順が並ぶか
- セットアップの driver 選択: imx708 など ov9281 以外のカメラ、hifiberry 以外のスピーカーで、セットアップを通しで実行できるか。カメラ HAL の既定（解像度、モノクロ前提）が合うか
