- 読者と用途: 塗布量-直径校正を実施・保守する技術者/開発者。この文書を読んで、校正ジョブの使い分け・校正ファイルの扱い・信頼できる範囲・診断結果の判断を誤りなく行う。

## 評価用問題
### Q1 塗布量校正の生成ジョブで、中心 view だけでは検出失敗が出るようになった。どのパラメータをどう変えるか。
- 要点: `view_count`（周辺 view 数）を 0 から上げる
- 要点: 周辺 view の役割は検出失敗時のフォールバック（精度向上ではない）

### Q2 収集済みの session で、検出ハイパラだけを変えて校正を作り直したい。`paste_volume_calibration` と `paste_volume_refit` のどちらを使うか。理由も。
- 要点: `paste_volume_refit`
- 要点: 装置不要で数秒で終わる（収集ジョブは実機・約 1 時間・ペーストが要る）

### Q3 再フィットで検出ハイパラを試すだけで、Git 管理の保存先に校正ファイルを残したくない。どうするか。
- 要点: `save_name` を空にする（診断だけが出て保存されない）

### Q4 塗布量校正の生成ジョブ（収集側）で `save_name` を空にして実行した。校正ファイルは保存されるか。
- 要点: 保存される（「保存しない」は選べない）
- 要点: ペースト・ノズル径・塗布高さと時刻から自動命名される

### Q5 校正ファイルの `detection` から `min_area_px` キーが欠けている。読み込み時に既定値で補われるか。理由も。
- 要点: 補われず、校正の読み込みが拒否される
- 要点: 既定値で埋めると、既定値を将来変えたときに既存ファイルの意味が静かに変わるため（検出ハイパラは校正と不可分）

### Q6 運転時キャリブレーションのログで、ある点が `diameter_below_reliable_range` で不採用になった。その点の直径はどこにあり、補正に使われるか。
- 要点: 被覆域の中だが、信頼できる範囲の下限（`reliable_diameter_min_mm`）未満
- 要点: 補正の材料にしない（不採用）

### Q7 被覆域が 0.60〜1.20 mm の校正を運転時キャリブレーションで使う。採用される直径の範囲は何 mm から何 mm か。
- 要点: 下限 0.81 mm（0.60 + 0.35 × 0.60）
- 要点: 上限 1.20 mm（被覆域の上限のまま）

### Q8 ノズル径の違う session を、既存の校正で推定した。推定器はこの条件の不一致を理由に推定を断るか。
- 要点: 断らない（推定器は条件を照合しない）
- 要点: 照合・報告は評価側の責務（断ると条件不一致の session を評価できなくなる）

### Q9 新しい校正の診断で `monotonic_in_range` が true だった。これでデータが健全と判断してよいか。データの異常を見るには何を見るか。
- 要点: 判断できない。単調性は保証されているので常に真
- 要点: `residual_relative_std` と `point_relative_mae` を見る
- （2 次・1 次係数がちょうど 0 なら純 3 次への退避が起きた、は加点要素。必須にしない）

### Q10 校正を評価したら点ごとの誤差が ±10% を超える点が多かった。これを理由に校正を失敗と判断してよいか。その理由と、主基準は何かも答えよ。
- 要点: 失敗と判断しない。教師ラベルは総質量を指令回転数比で配分した値で、点ごとの真値ではないため点ごと誤差は原理的に評価できない
- 要点: 主基準は session 総体積の相対誤差

### Q11 1 view の直径計測で、blank ガードと Otsu による 2 値化はどちらが先か。先にする理由も。
- 要点: blank ガードが先（差分の分位点が `min_contrast` 未満なら直径 0 で終える）
- 要点: Otsu は必ず何かを 2 値化するので、単独では blank セルの背景ノイズを誤検出するため

## 保留問題
### H1 収集ジョブで、検証に使う校正に既存の X を指定し、保存名にも X と同じファイルになる名前を入れて実行した。何が起こるか。理由も。
- 要点: 収集を始める前にジョブが断る
- 要点: 同じ session で作った校正で同じ session を検証すると総体積誤差がほぼ 0 になり、汎化を測ったように見えるため

### H2 収集ジョブの最後で、blank 誤検出のためにフィットが断られた。収集した dataset はどうなり、次に何をすればよいか。
- 要点: ジョブは失敗にならず警告に留まり、dataset は残る
- 要点: 検出ハイパラを変えて `paste_volume_refit` で作り直す

### H3 推定器に 3 channel でない画像を渡した場合と、はんだが写っていない画像を渡した場合で、推定結果の不採用理由はそれぞれ何か。
- 要点: 前者 `image_invalid: <理由>`（構造的不正、呼び出し側のバグ）
- 要点: 後者 `no_deposit_detected`（正常系）
- （どちらも例外ではなく不採用として返る、は問題文が前提にしているので要点にしない）
