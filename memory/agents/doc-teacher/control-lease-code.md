# src/web/api/control.py（ControlLease docstring）理解度テスト

## 対象
- ファイル: src/web/api/control.py（モジュール docstring、ControlLease のクラス・メソッド docstring）
- 読者と用途: backend を保守する開発者。操作権リースに手を入れる前に読み、自動解放をしないこと、空きに戻る経路、WebSocket 接続数を数える目的、on_change の呼ばれ方を誤解なく把握する。

## 事実確認（R1 執筆時）
- 空きに戻すのは `release`（保持者自身のみ）とプロセス再起動だけ。`takeover` は `_assign` で保持者を替えるだけで空きにはしない
- `_assign` は `self._holder != identity` で変化判定。`ClientIdentity` は `attrs.frozen` で eq が全フィールド比較なので、同一 session_id でも display_name が違えば変化扱い → on_change が呼ばれる（実行で確認: 同名再 claim は 0 回、改名 claim は 1 回）
- 拒否された claim は `changed=False` のまま `_notify` → on_change なし
- `_notify` は `with self._lock` の外で呼ばれる。Lock は非再入なので、ロック内で呼べば on_change からの snapshot はデッドロックする
- connect / disconnect は `_notify` を呼ばない
- on_change の実体は app.py `_control_change_notifier`（全 WS 購読者へ配信）

## 評価用問題
### Q1 保持者がブラウザのタブを閉じ、その WebSocket 接続がすべて切れたまま 10 分経った。別のユーザーが操作したい。この時点でリースはどうなっているか。別のユーザーはどのメソッドで操作権を得るか。
- 要点: リースは元の保持者が保持したまま（時間・切断で失効しない）
- 要点: `takeover` を使う（`claim` では得られない）

### Q2 「保持者の WebSocket 接続数が 0 になったら一定時間後に操作権を解放する」処理を `disconnect` に足す案が出た。この案は現在の設計方針に合うか。接続数は何のために数えているか。
- 要点: 合わない（自動解放はしない方針）
- 要点: 接続数は `LeaseInfo.connections` の表示のためだけで、失効判定には使わない

### Q3 操作権が空き（`held=False`）に戻る経路をすべて挙げよ。`takeover` はその経路に含まれるか。
- 要点: 保持者自身の `release`
- 要点: プロセス再起動（リースはメモリ上だけ）
- 要点: `takeover` は含まれない（保持者を替えるだけで空きにはしない）

### Q4 session_id が `s`、表示名 `A` のクライアントが保持者である。同じ session_id のクライアントが (a) 表示名 `A` のまま `claim` を呼ぶ、(b) 表示名 `B` で `claim` を呼ぶ。それぞれ `on_change` は呼ばれるか。
- 要点: (a) 呼ばれない
- 要点: (b) 呼ばれる（`ClientIdentity` の値で比較するため、表示名の変化も保持者の変化とみなす）

### Q5 `on_change` の中で `lease.snapshot()` を呼び、最新状態を配信したい。これは安全か。理由も答えよ。
- 要点: 安全
- 要点: `on_change` は内部ロック解放後に呼ばれるので、デッドロックしない

### Q6 ジョブ実行中に別のクライアントが `takeover` した。実行中のジョブはどうなるか。
- 要点: ジョブは止まらない／触られない
- 要点: 移るのは指示を出す権利（操作権）だけ

### Q7 クライアント Y が保持中に、別のクライアント Z が `claim` を呼んだ。何が起きるか。`on_change` は呼ばれるか。
- 要点: `ControlDeniedError` が送出される（保持者 Y の表示名を持つ）
- 要点: 保持者は Y のまま
- 要点: `on_change` は呼ばれない

## 保留問題
### H1 保持者でないクライアントが `release` を呼んだ。例外は出るか。リースと `on_change` はどうなるか。
- 要点: 例外は出ない（無効果、冪等）
- 要点: 保持者は変わらず、現在の状態を返す
- 要点: `on_change` は呼ばれない

### H2 保持者が同じセッションで 2 つのタブを開き、WebSocket を 2 本つないでいる。1 つのタブを閉じた後の `LeaseInfo.connections` と保持状態は。
- 要点: connections は 2 → 1（同一セッションの多重接続も数える）
- 要点: 操作権は保持したまま

### H3 backend をアップデートで再起動した直後、操作権は誰が持っているか。
- 要点: 誰も持っていない（空き）
- 要点: 理由はリースがメモリ上にしか無いため
