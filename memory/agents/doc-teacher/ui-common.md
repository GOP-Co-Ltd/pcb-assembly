# WebUI 共通テンプレート 理解度テスト

## 対象
- ファイル: src/web/ui/templates/ 配下の pasting/ 以外（base, job, message, settings, tab, update, dev/*, partials/*, posctrl/*）
- 読者と用途: 装置のオペレーター。WebUI の共通部分（マシン選択、操作権、ジョブ実行、設定、更新、カメラ校正、基準点設定、銅箔検出）を画面の案内だけで迷わず操作する

## 確認した事実（R1）
- 緊急停止: POST /api/emergency-stop は jobs.request_abort() 後に Klipper emergency_stop。操作権不要。復帰は FIRMWARE_RESTART（ファームウェア再起動は操作権要・確認ダイアログ・pcbasm サービスも再起動）
- 操作権: control.js。held 以外は data-requires-control に inert。取得=free 時、解放=held 時、奪取=viewer 時に表示
- 基準点設定 (web/api/jobs/posctrl.py): カメラ校正ファイル必須 → 全軸ホーミング → calibration.z_position へ移動 → ジョグ待機。record で XY を reference_point.x/y に即時反映しジョブ終了。quit は設定を変えず中止
- カメラ校正: confirm prompt（続行/中止）→ 撮影・検出、失敗なら再 prompt。撮影時の Z を z_position に保存。apply（設定に反映 / 破棄）で camera.calibration_file を設定。square_size は persisted_params
- フォーカスZ = 校正ファイルの z_position（state.focus_z）。None ならボタン disabled
- Relax = M84
- 銅箔検出: スライダーはプレビューのみ。「設定に保存」で paste_dispenser.pad_align.canny_low/high を PUT
- 設定ページ: settings.js が入力を debounce して PUT（自動保存）。空欄は data-allow-empty 以外保存しない
- 機体更新: 装置使用中（busy_owner）は 409。dirty / ahead / detached / upstream 無しは blocker。「更新して再起動」は update_available のときだけ有効
- マシン操作パネル: 対話ジョブ（accepts_commands）実行中は WS command へ、他のジョブ中は disabled
- tests で検査されている文言: 「緊急停止」「設定に保存」、canny 系 id/値 → 変更していない

## 評価用問題
### Q1 別の端末が操作権を持っている。自分の端末からジョブを実行したい。何を押すか。押すと相手の端末はどうなるか。
- 要点: 「奪取」を押す／相手は閲覧のみになる（操作できなくなる）
### Q2 操作権を持っていない端末で、「緊急停止」とジョブの「中止」は押せるか。
- 要点: どちらも押せる（操作権に依らず誰でも押せる）
### Q3 新しく立ち上げた機体で「カメラキャリブレーション」と「基準点設定」をする。どちらを先にするか。理由も。
- 要点: カメラキャリブレーションが先／基準点設定はカメラキャリブレーション（の結果・Z）を使うため
### Q4 「基準点設定」の実行ボタンを押した直後、装置はまずどう動くか。
- 要点: 全軸をホーミングする／カメラキャリブレーション時の Z へ移動する
### Q5 基準点設定の途中で、今の位置を保存せずに作業をやめたい。どのボタンを押すか。Record を押した場合との違いも答えよ。
- 要点: Quit／Quit は設定を変えない／Record は現在の XY を設定へ即時反映してジョブを終える
### Q6 緊急停止を押した後、装置を再び動かせるようにするには何をするか。そのとき画面はどうなるか。
- 要点: 「ファームウェア再起動」を押す（操作・設定メニュー、操作権が要る）／確認のうえ WebUI のサービスも再起動し画面が一時的に切れる
### Q7 銅箔検出調整でスライダーを動かし、良い値が見つかった。値を装置に残すには何をするか。
- 要点: 「設定に保存」を押す（R1 で「スライダーだけでは保存されない」を要点から外した。問いが理由を求めていないため）
### Q8 カメラキャリブレーションを実行する前に、Z をどうしておくか。理由も。
- 要点: プレビューでピントが合う Z に合わせる／撮影時の Z がフォーカス Z として記録される
### Q9 カメラキャリブレーションのジョブが終わり、結果が表示された。この結果を装置の設定に使うには何をするか。
- 要点: 「設定に反映」を押す（「破棄」なら設定は変わらない）
### Q10 マシン操作パネルの「フォーカスZへ」ボタンが押せない（灰色）。原因と解消方法は。
- 要点: カメラキャリブレーションが済んでいない（記録された Z がない）／カメラキャリブレーションを実行して設定に反映する
### Q11 機体のソフトウェア更新ページを開いたが「更新して再起動」が押せない。最初に何をするか。
- 要点: 「更新を確認」を押す（R1 で 2 点目を要点から外した。問いは「最初に何をするか」だけを求めている）
### Q12 マシン設定ページで値を書き換えた。保存するために何をするか。また、この端末が操作権を持っていない場合はどうなるか。
- 要点: 何もしなくてよい（自動保存）／操作権がなければ編集できない（先に取得する）
- R1 で問題文を修正した。旧問題文は操作権を問わないのに、要点に入れていた

### Q13 塗布ジョブの実行中に、機体のソフトウェア更新をしてよいか。
- 要点: できない（ジョブの実行中は更新しない）
- 保留 H3 から移した。汎化確認で要点の 2 点目「ジョブが終わってから行う」が欠けて不正解になったが、これは問いが求めていない要点だったため外した（問題不良）

## 保留問題
### H1 マシン操作パネルの Z バーで、ヘッドを上に逃がしたい。+ と − のどちらのボタンを押すか。
- 要点: マイナス（−）側。この機械は上昇で Z が減る
### H2 ジョブが入力待ちのダイアログを出しているが、操作権は誰も持っていない。自分の端末で応答するにはどうするか。
- 要点: 操作権を「取得」してから応答する（応答できるのは保持者だけ）
