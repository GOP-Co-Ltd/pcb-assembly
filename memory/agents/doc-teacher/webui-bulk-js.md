# src/web/ui/static/js/bulk.js コメント 理解度テスト

## 対象
- ファイル: src/web/ui/static/js/bulk.js（冒頭の説明と行内コメントだけ。コードは変えない）
- 読者と用途: WebUI を保守する開発者。一括管理ページ（/bulk）の行操作を直す・機能を足す前に読み、行ごとに WS を張る理由、prefix の扱い、ボタンが押せる条件、状態を取り直す契機を誤解なく把握する

## 確認した事実（R0）
- app.js: `BASE = body.dataset.machineBase ?? ""`。/bulk では空。`withBase(path, base = BASE)` は今回 base 引数を追加。fetchApi は `fetch(withBase(url))` なので api() は BASE（空）しか付けない
- 行の base は bulk.html の `data-row-base="/m/{{ machine_id }}"`
- control.py ControlLease: `disconnect_grace=30.0`。保持者の接続 0 本から 30 秒超で解放。`idle_timeout=600` は busy() 中は止まるが、切断猶予の失効は busy に関係なく発生（`_expire_stale`）
- 接続数は session_id ごと（`/api/ws` の lease.connect / disconnect）
- WS イベント: control_changed（app.py で lease 変化時）、state_changed（PCB の PUT/アップロード等で publish）
- refresh() の契機: WS open / close / REFRESH_EVENTS / run() の finally。refreshUpdate() は WS open だけ
- render(): 取得は held・unknown で hidden、pending・viewer で disabled。解放は held 以外で hidden。更新・塗布実行は pending か held 以外で disabled
- refresh() の失敗（不通）は unknown にしてトーストを出さない

## 評価用問題
### Q1 一括管理の行に、その機体の GET /api/jobs を叩く処理を足す。行の base が "/m/abc" のとき、api() にどんなパスを渡すか。
- 要点: "/m/abc/api/jobs"（`${base}/api/jobs`）を渡す
### Q2 「行ごとの WS をやめて、5 秒おきに GET /api/state をポーリングすれば十分では」という提案があった。採用すると何が起きるか。backend がそうする理由（判定の仕組み）も答えよ。
- R1 で問題文を修正（問題不良）。旧問題文は「何が起きるか」だけを問い、要点 1 点目の仕組みを求めていなかった
- 要点: 保持者の WS 接続が 0 本のまま 30 秒経つと backend が操作権を解放する／ジョブ（塗布）実行中でもこの失効は止まらず、行で取った操作権が塗布の途中で失われる
### Q3 ある行の機体を別の端末が保持している。その行の「取得」「更新」ボタンはそれぞれどう見えるか。
- 要点: 取得は表示されるが押せない／更新は押せない
### Q4 行の機体の電源が落ちた。行の state が変わるまでの流れを答えよ。また変わった後、「取得」「解放」「更新」「塗布実行」の各ボタンは隠れるか、表示されたまま押せないか。
- R3 で問題文を修正（問題不良）。旧問題文は「流れ」を問い、ボタンごとの結果を求めていなかった。R3 の解答「disabled/hidden に変わる」は文書の表を見ているが、問いがボタン別の答えを要求していなかった
- 要点: WS の close を契機に状態（GET /api/state）を取り直す／GET が失敗して unknown（不通）になる／取得と解放は隠れる／更新と塗布実行は表示されたまま押せない
### Q5 backend が新しい WS イベント "jobs_changed" を送るようになった。行の状態をこのイベントでも取り直したい。どう変えるか。ポーリングを足してよいか。
- 要点: REFRESH_EVENTS に "jobs_changed" を加える／ポーリングは足さない
### Q6 行の「更新」で機体が更新され再起動した。行の「ソフトウェア」欄の要約が新しい内容に変わるのはいつか。
- 要点: 再起動後に WS が再接続して open したとき（GET /api/update/status を取り直す）
### Q7 行の WS の URL を組むとき、api() と同じように `${base}/api/ws` ではなく withBase を使っているのはなぜか。また withBase に何を渡すか。
- 要点: WS は api() を通らない（api() が使えない）ため／withBase("/api/ws", base) と行の base を第 2 引数で渡す
