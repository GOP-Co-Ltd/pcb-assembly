# solo-dev-cycle skill の追加

worktree `docs+20260730+solo-dev-cycle` / ブランチ `docs/20260730/solo-dev-cycle`。
本タスク自体を、これから書く solo-dev-cycle の 5 段階でドッグフーディングする。

## 段階 1: 計画

### 要件

サブエージェントに委譲せず、単一エージェントが 5 段階（計画 → テスト実装 → 機能実装 →
リファクタリング → ドキュメント）でロールを切り替えながら逐次進める開発フローの手順書を
`.claude/skills/solo-dev-cycle/SKILL.md` として追加する。名前はユーザー確定で `solo-dev-cycle`。

### 位置付け

`agent-team-startup` の工程（planner → spec-test-author → plan-implementer → code-reviewer →
code-simplifier）と同じ骨格を、委譲コスト（文脈の再構築・報告の往復）なしで回す版。
両者は排他で、SKILL.md 冒頭に使い分け表を置く。

### 構成（公開 IF 相当 = 見出し構成）

1. `agent-team-startup` との使い分け
2. 原則（委譲しない / 段階を飛ばさない / ロールを混ぜない / 切替を宣言する）
3. 5 段階の詳細（目的・触ってよい範囲・やらないこと）
4. 段階ゲート表（各段階の完了条件と検証コマンド）
5. 自己レビューの弱点への対処（writer-verifier が同一 context になる問題）
6. 段階の省略基準
7. 記録先
8. 参照

### 設計判断

- **記録先を `memory/agents/<セッションのエージェント名>/<task-slug>.md` の 1 ファイルに集約**。
  ロールごとにフォルダを分けない。単一 context なので引き継ぎ用の分割が不要で、
  既定 `orchestrator/` は `memory/agents/README.md` の既存規約にそのまま乗る。
- **自己レビューの弱点を明記する。** チーム版では code-reviewer が独立 context だが、ソロでは
  実装した本人が読み直すため見落としが構造的に増える。記憶ではなく diff を根拠にする、
  計画書と突き合わせる、チェックリストで見る、の 3 点を段階 4 の手順に含める。
- **委譲の例外を 1 つだけ残す。** 設計上の裁定に迷う場合に限り code-reviewer への単発委譲を
  許す（ユーザーが委譲を禁じていない場合）。逃げ道を塞ぐと品質が落ちるため。
- **`.agents/`（Codex ミラー）には追加しない。** ミラーは Codex 側の `migrate-claude` skill が
  判断込みで行う運用で、全 skill が同期されているわけでもない（compact-prep / edit-dot-claude は未ミラー）。
  今回の依頼範囲外。

### 受け入れ基準（段階 2 で確定 → 段階 4/5 で照合）

機械的に検査できるものはチェックスクリプト（段階 2）で、内容の妥当性は段階 4 の
自己レビューで照合する。

### リスク（段階 1 時点）

- 手順書が長くなりすぎて読まれない → agent-team-startup（126 行）と同程度に収める
- チーム版と内容が重複して二重管理になる → 共通規約（テスト方針・検証コマンド・実機禁止）は
  既存 skill / CLAUDE.md への参照で済ませ、この skill には「ソロ固有の差分」だけを書く

## 段階 2: テスト実装

Markdown 成果物なので pytest は使えない。受け入れ基準をチェックスクリプト
（`/tmp/dot-claude-work/solo-dev-cycle-check.sh`、リポジトリには含めない）に落とし、
実装前に走らせて red（SKILL.md 不在 / CLAUDE.md 未登録）を確認した。検査項目:

frontmatter の name とディレクトリ名の一致 / description の長さ / `</content>` 混入なし /
5 段階すべてが見出しに存在 / agent-team-startup との使い分け・記録先・検証コマンド・実機禁止への言及 /
相対リンクがすべて解決 / 150 行以内 / CLAUDE.md 参照先マップに登録。

## 段階 4: 自己レビュー

diff を通しで読み直して 3 件。すべて対応済み。

1. **must-fix — 原則と例外の矛盾**: 「Agent tool を使わない」と書きながら、自己レビュー節で
   `code-reviewer` への単発委譲を許していた。原則側に例外の所在を明記して解消。
2. **must-fix — 省略基準が自己レビューを穴にしていた**: 「段階 4 を省略可」と書くと、ソロで
   最も重要な自己レビューまで飛ばせてしまう。「段階 4 の**整理**を省略可、自己レビューは省略
   しない」に修正。
3. **should-fix — 段階 2 ゲートが実行手段を示していなかった**: 「新規テストだけを実行」に
   `pytest <path>` を添えた。

却下: 使い分け表の「委譲せず指示された」行と「1〜数モジュール」行の統合。前者は指示ベース、
後者は規模ベースで発火条件が別物のため残す。
