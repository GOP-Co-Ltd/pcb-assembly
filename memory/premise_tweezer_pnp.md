# PnP はピンセットでつかんで置く方式（2026-11-02）

部品実装（`[pnp]`、`src/pcbasm/pnp/`）の機体は、一般的な PnP 機のように
ノズルとエアで部品を吸着して運ぶのではない。**ピンセットで部品をつかみ、基板上に置く**。
人間がピンセットで部品を置く動作を機械で行う、新しい方式である。

## 機体の構成（2026-11-02 時点）

- 自由度は **4+1**: XYZ ステージ + ピンセットの回転（θ）の 4 軸と、ピンセットの開閉 1
- X / Y / Z は塗布機と同じく stepper（Klipper）
- ピンセットの回転と開閉は、それぞれ別の 360 度サーボで動かす。サーボは Feetech STS3032（2 台）
- サーボは FEETECH URT-2 経由の UART で Raspberry Pi につなぐ。Klipper にはサーボ用の拡張もマクロも入れていない。Python から直接制御する想定
- 制御には強化学習（RL）を多く使う予定。それに向けて、XYZ は Klipper の MCU ファーム（C）に速度指令のモジュールを足したもので動かし、PnP 機では Klippy を使わない方針（2026-11-10。Zig は検討して見送り）。理由は次の 2 つ
    - 「速度 v で動き続ける」ような、コントローラからの連続的な指令を使いたい（G-code を送って止まるのを待つ方式ではなく）
    - ツールヘッドの接触をロードセルで検知したら即時に止めたい（エラーではなく、ただ止める）
- ファームのハードウェアは BTT SKR Pico（塗布機と同じボード）。ファームは `src/firmware/pnp-motion/` に置き、そこだけ GPLv3。リポジトリの既定（pcbasm など）は MIT で、Klipper のコードを取り込まない（リポジトリは OSS で公開、ハードウェアは CERN OHL の予定）。設計案は `docs/design/pnp-tweezer-motion.md`
- カメラは **2 系統**:
    - トップカメラ: 位置合わせ用（塗布機と同じ役割）
    - フロントの RGB 広角カメラ: ステージ全体を見渡す

**Why:** ユーザーが PnP 実装に着手する際に、前提条件として明示した。

**How to apply:** PnP の設計・実装・文書では、吸着ノズル・負圧・バキュームセンサー・
ノズル交換といった吸着式 PnP の概念を前提にしない。部品の保持・解放は
ピンセットの開閉（つかむ・離す）として扱う。一般的な PnP の慣習（OpenPnP 等）を
持ち込むときは、ピンセット方式に当てはまるかを先に確かめ、不明ならユーザーに確認する。
