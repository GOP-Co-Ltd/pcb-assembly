# posctrl

Board/オフセットの位置合わせを担う共通制御モジュール。

- マシン初期化と Board 変換計測のセットアップ
- Board / 位置 / オフセットの調整
- 設計銅箔のカメラ投影と観測エッジ照合（chamfer、並進のみ・サブピクセル）による位置ずれ算出
- 照合する関心領域の幾何計画（`AlignmentRegion` / `plan_alignment_regions`）
- 領域単位の反復計測（`RegionAligner` / `RegionAlignment`）と、pad ごとに最近傍の区の変位を引く局所補正（`BoardAlignment` / `RegionAlignmentSession`）
- Board 巡回用のカメラ表示

観測は `observe() -> Transform`（カメラ mm 空間、原点=画像中心、想定→観測）契約の observer で統一している。

## 銅箔照合の設計

- **1 区の照合で推定するのは並進のみ**。ROI 1 枚では微小回転が測定可能な信号にならないため、区の内部では並進しか見ない。並進は 3 点放物線でサブピクセルまで補間する
- 一方向のエッジしか無い領域ではコスト曲面が縮退して並進が決まらない（開口問題）。`EdgeMatch.sharpness`（コスト曲面の弱軸方向の曲率）で検出し、`min_sharpness` を下回る照合は棄却する
- 領域は撮像前に幾何だけで選ぶ（`plan_alignment_regions`）。pixel 空間に一辺 `region_size_px` の**重なりのないタイル格子**を張り、格子の位相は塗布対象 pad 中心の重心に合わせる（タイル位置がタイル数に依存しないので、board 変換の回転で格子が跳ばない）。採否は「ROI 全体が `safe_area` に収まる」「区内に塗布対象 pad の中心が 1 つ以上ある」「予測 sharpness が `min_sharpness` 以上」の 3 条件だけで、条件を満たす区は上限なく全部使う
- 予測 sharpness は、想定エッジを約 1px 間隔の点に落とし、ROI に入った点の単位法線から積んだ `λ_min(Σ n nᵀ)` を点の数で正規化して出す。点の数で正規化するのは、実測 `sharpness` が template 画素数で正規化されているため
- `safe_area` は基板外形を `board_edge_margin` [mm] 縮めた領域。外周はやすり掛けで銅箔が削れやすく、さらに基板外形線は投影する想定エッジに含まれないため、視野に入ると片方向 chamfer ではペナルティを受けない偽エッジとして働く。領域選定の定義域と外周除外を同じ図形で決めている
- 各区は**最大 `max_passes` 回まで反復計測**する。2 パス目以降は累積変位を board 変換の後段へ挿した投影器で投影する（ステージを動かすと想定投影と観測が画像内で同じだけ動くので、投影を補正しないと同じ変位を二重に測る）。増分が `converge_tolerance` [mm] 以下になったら打ち切る
- 補正は**区ごとの局所値をそのまま使う**（`BoardAlignment.correction_for`）。pad は board 座標で最も近い成功区の変位（純並進）を引く。区は等サイズの正方格子タイルなので「最近傍の区中心」は実質「その pad を含む区」になり、含む区が無い（計画外・照合失敗）pad にも同じ規則で最近傍の成功区が当たる（包含判定とフォールバックの場合分けが要らない）。厳密に「最近傍＝包含」なのは board→pixel が相似写像のときだけで、3 点法の `board_transform` はスキューを持ち得るが、外れるのは区境界のごく細い帯だけ（実測でスキュー 0.06° なら 1.4um、1° でも 27.9um の幅）。照合ノイズ（区あたり 5um 級）以下なので実用上は問題にならない。平均や大域アフィンで均さないのは、実銅箔が設計から局所的にずれる（エッチングのレジストレーション誤差・基板の伸び・反り）ため — 実測で隣接区の変位が 3.3mm 離れただけで 0.36mm 違い、大域アフィンでは残差 RMS 114um（照合ノイズの 20 倍以上）が残った。平均・当てはめはこの情報を捨てる行為になる。区の変位の平均とばらつきはログ用の指標としてだけ持つ
- 外周付近のタイルは ROI が `safe_area` に入らず落ちるので、**全区が成功しても自分の区を持たない pad が残る**。その pad は離れた区の補正を借りることになり、局所ずれには勾配があるぶん借用距離がそのまま誤差の上限になる。`BoardAlignment.borrowed_corrections` が借用の件数と距離（中央値・最大）を返し、塗布ジョブがログに出す。救済は自動化していない — `board_edge_margin` や `region_size_px` を実機で詰めるための判定材料
- 設計 board 座標のポリゴンを書き換えることはせず、補正は**機械座標へ出る瞬間**（塗布の変換合成 `board → correction → toolhead → height`）に pad ごとに 1 回だけ適用する。この合成順はドメイン規則なので job 側で組まず、`corrected_board_transform`（board → カメラ機械座標）と `PasteSession.pad_to_machine`（→ ノズル機械座標 + 高さ面）が持つ。pad 列に対しては `corrected_pad_targets`（巡回先の点）と `PasteSession.pad_transforms`（塗布用の変換）が **入力順・同数** で返すので、「どの pad にどの補正を当てたか」の対応が呼び出し側のループの書き方に依存しない（塗布ジョブは初回パージ pad を先頭に足した 1 本の列をスライスして使う）

ペースト塗布と Pick and Place の双方から利用する。
