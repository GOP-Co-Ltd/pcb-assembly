# HAL

Hardware Abstraction Layer: カメラ・Klipper（Moonraker 経由）・新ファーム（pnp-motion）の XYZ ステージ・音声出力・ピンセットのサーボ・Xbox コントローラを扱うクラスを置く。
画像処理は `pcbasm.vision`、塗布や位置合わせの手順は `pcbasm.pasting` / `pcbasm.align` に置く。

## MCU プロトコルクライアント（`mcu/`）

pnp-motion ファーム（Klipper の MCU のプロトコルで話す）とシリアルで直接話すクライアント。Klippy を介さない。
公開名は `pcbasm.hal.mcu` から re-export している（`pcbasm.hal` からは出さない）。
MCU を開く口は `open_motion_stage` と `send_emergency_stop` だけで、呼ぶのは `pcbasm.machine.devices` だけにする（テストは root conftest の `forbid_real_motion` が塞ぐ）。

| モジュール      | 役割                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `wire.py`       | CRC16、VLQ、メッセージブロックの組み立て `encode_block` と分解 `BlockReader`（純粋）                                                                                                                                                                                                                                                                                                                                                    |
| `dictionary.py` | identify で読むデータ辞書 `DataDictionary`（メッセージの符号化・復号、列挙、定数）と、復号したメッセージ `Message`（純粋）                                                                                                                                                                                                                                                                                                              |
| `transport.py`  | シリアル通信 `McuTransport`。ブロックの送り直し、`identify`、`send`、応答を待つ `query`、受信スレッドで呼ぶ `subscribe`。shutdown の間は、shutdown 中も受け付けるコマンドだけを送り、ほかは `McuShutdown`。`clear_shutdown` に ack が来たら元に戻る                                                                                                                                                                                     |
| `clock.py`      | MCU の clock とホストの時刻の対応。推定 `ClockEstimator`（純粋）と、`get_clock` を周期的に送る `ClockSync`                                                                                                                                                                                                                                                                                                                              |
| `tmc2209.py`    | TMC2209 のレジスタの値 `register_values`（`TmcSettings` から）と、UART の datagram の組み立て・復号（純粋）                                                                                                                                                                                                                                                                                                                             |
| `errors.py`     | `McuError`（`DeviceError` 派生）と `McuShutdown`                                                                                                                                                                                                                                                                                                                                                                                        |
| `settings.py`   | ステージの設定 `McuMotionSettings` / `AxisSettings` / `LoadCellSettings`（hal の値型。`pcbasm.config` は読まず、`pcbasm.machine.devices.motion_settings` が `[pnp.motion]` から作る）。ファームの前提（ステップの上限、周期と期限）を作るときに確かめる                                                                                                                                                                                 |
| `firmware.py`   | pnp-motion ファームの操作 `PnpMotionFirmware`。接続時のファームの確認、設定の列と crc（同じ設定なら reset せずに使い回す）、TMC2209 の設定と IFCNT での確認、`velocity_stream` の開始・速度・停止・状態の問い合わせ、可動域を書き換えて流す移動 `travel`、リミットスイッチとロードセルの接触停止（`trigger_analog`）を同じ trsync に張る・外す、常に点ける LED とロードセルの設定。緊急停止だけのために開いて送る `send_emergency_stop` |

| `load_cell.py`  | ロードセル（HX711）の読み取り。`sensor_bulk_data` の復号 `decode_samples`、グラムへの換算と自動・手動のタール、Z が止まっている／動いている区間の荷重の幅 `LoadTracker`（時刻を引数で受ける純粋なロジック）、`query_hx71x` で読み始めて受信スレッドで `LoadTracker` を回し、タール値を MCU の `sos_filter` へ送る `LoadCell`。接触保持から戻る判定 `released`                                                                           |
| `stage.py`      | `MotionStage` の MCU 版 `McuMotionStage` と生成口 `open_motion_stage`。mm をステップに直し、原点出しを済ませた軸をホストで覚える。操作は 1 つずつ実行し、`emergency_stop` と `status` は操作の終わりを待たない。ロードセルの接触で止まったら、次の操作の最初で接触保持に入り（MCU の可動域も縮める）、荷重が下がれば戻す                                                                                                                |

- ファームの仕様（`Protocol.md`、`MCU_Commands.md`、C ソース）は GPLv3。pcbasm は MIT なので、Klippy（`klippy/`）のコードは読まず、構造も写さない。各モジュールの docstring に、仕様として読んだ出典を書く
- テストは実機に触れない。`tests/support/wire_mcu.py` の MCU 役（子プロセス）と pty で話し、辞書は `tests/support/mcu_dictionary.py` で合成する（ファームのビルド出力はリポジトリに置かない）
- 原点出しや座標指定の移動の手順は、ファームの README と C ソースを仕様として読んで組み立てた。`tools/bench.py`（GPLv3）は、ホストが送るコマンドの順を確かめるためにだけ読み、名前・構造・コメント・式の形は写していない（`firmware.py` と `homing.py` の docstring にも書く）
- 原点は MCU が覚えないので、backend を起動し直したときや `restart` の後は「未」から始まる。MCU が同じ設定で設定済みなら reset せず（励磁を切らず、Z を落とさない）、流れを止めて可動域を戻してから使う

## 機械を動かす流れ

1. `XYZStage` / `ManualStepper` / `AirPump` / `PasteDispenser` は `KlipperClient` を受け取り、状態と printer.cfg を読む
2. これらのメソッドは機械を動かさず、`pcbasm.gcode.GCode` を返す
3. 呼び出し側が返った `GCode` を `KlipperClient.send_gcode()` で送って初めて機械が動く
4. ジャーナル（`pcbasm.machine.journal.Journal`）を渡した接続では、`send_gcode()` は送る前にブロックをそこへ書く
5. `MoonrakerKlipper.connection()` / `FakeKlipper.connection()` は 1 つのクライアントを共有したまま、既定の timeout とジャーナルだけを替えた接続を返す。`MoonrakerKlipper` は `printer.cfg` を接続ごとに最初の 1 回だけ読む

`KlipperClient` の実装は `MoonrakerKlipper` と `fake.FakeKlipper` の 2 つに限る。

## 変更時の注意

- 新しいデバイスを足すときも、上の流れに合わせて「`KlipperClient` で設定を読み、`GCode` を返す」形にする
- 機械設定（TOML）から Klipper とカメラを組み立てるのは `pcbasm.machine.devices` だけ。`open_klipper` と `open_servo_bus` を呼ぶのもそこだけにする。HAL は `pcbasm.config` を読まない（`open_klipper` の接続先、通知音の出力先と音量は値で受け取る）
- fake は `fake.py` に 1 系統だけ置く。テスト用に別の fake を作らず、足りない模擬はここへ足す
- テストは実機に触れない（`open_gamepad` もテストからは呼べない。`EvdevGamepad` は `/dev/uinput` の仮想デバイスで確かめ、書けない環境では skip する）。実機での確認は [実機受け入れ試験](../../../docs/acceptance.md) に書く
